# AI Fabric Privacy Shield

## Scenario

This app demonstrates privacy-first handling for customer-facing AI/support messages. A user can
submit text containing sensitive information, and the app runs the input through AI Fabric PII
detection before it stores or indexes support data.

The public demo name is **AI Fabric Privacy Shield**. It is designed to show framework users how to
protect AI app sessions when customers paste emails, phone numbers, SSNs, order details, or other
sensitive text into an assistant/support flow.

## AI Fabric Capabilities Proved

- PII detection activates through configuration.
- Redaction mode stores safe support-message content.
- Original payload storage can be hash-based or AES-GCM encrypted depending on configuration.
- Plain-text PII is not returned by the public demo API after submission.
- Semantic search sanitizes the search query before it reaches AI Fabric vector search.
- Public demo sessions are isolated with session-scoped customer IDs.
- Governance/deletion services can be layered onto privacy-safe support data.
- The app can run locally without LLM keys or external vector infrastructure.

## Framework Surfaces

- `ai-fabric-starter`
- PII detection/redaction configuration
- `ai-fabric-governance`
- `ai-fabric-vector-lucene`
- `smoke-support` for deployment health metadata
- Spring Boot/JPA support-message persistence
- AI entity indexing for the `support-message` vector space

## Runtime Posture

Default runtime:

- H2 database
- local deterministic PII/search support
- no external LLM
- local Lucene vector index
- no external vector service dependency

Default port: `8093`.

## Run

From the repository root:

```bash
mvn -B -V --no-transfer-progress -f examples/real-apps/pom.xml -pl privacy-first-customer-facing-support -am package
java -jar examples/real-apps/privacy-first-customer-facing-support/target/privacy-first-customer-facing-support-1.0.0-SNAPSHOT.jar
```

## Docker Deploy

Dockerfile path:

```text
examples/real-apps/privacy-first-customer-facing-support/Dockerfile
```

Build from the repository root:

```bash
docker build -f examples/real-apps/privacy-first-customer-facing-support/Dockerfile \
  --build-arg AI_FABRIC_VERSION=0.5.3 \
  -t ai-fabric-privacy-shield:0.5.3 \
  examples/real-apps
```

Recommended public demo environment:

```bash
PORT=8093
CORS_ALLOWED_ORIGINS=https://ai-fabric.dev
AI_PII_MODE=REDACT
AI_PII_STORE_ENCRYPTED_ORIGINAL=true
AI_PII_ENCRYPTION_SECRET=<optional strong secret>
JAVA_OPTS=-Xms256m -Xmx768m
```

`/api/demo/health` exposes the deployed build metadata generated by the Dockerfile.

## Key Configuration

`src/main/resources/application.yml` enables PII handling:

- `ai.pii-detection.enabled=true`
- `ai.pii-detection.mode=REDACT`
- `AI_PII_MODE`: override redaction mode.
- `AI_PII_STORE_ENCRYPTED_ORIGINAL`: controls encrypted/hash original storage.
- `AI_PII_ENCRYPTION_SECRET`: when set, AES-GCM is used; when blank, original evidence is stored as
  `HASH:*`.

## Demo Flow

1. Create an isolated public demo session.
2. Seed sample support messages for that session only.
3. Submit a customer-facing message containing sensitive data.
4. Verify the public response returns processed/redacted subject and message fields only.
5. Search the safe AI Fabric index and verify the query is sanitized before retrieval.
6. Inspect privacy evidence: detection count, detection summary, mode applied, and original evidence
   policy.

- `GET /api/privacy-demo/search?sessionId=...&q=...&limit=...`
- `GET /api/demo/health`

- `GET /api/demo/samples`
- `POST /api/demo/seed`
- `POST /api/support/messages`
- `GET /api/support/messages`
- `GET /api/support/messages/{id}`
- `GET /api/support/privacy/customers/{customerId}/inventory`

## What This App Does Not Cover

- Chat-session action flow.
- Live LLM provider privacy behavior.
- RAG answer generation.

Use `chat-capabilities-demo`, `ai-fabric-account-resolver`, or provider RealAPI tests for those
paths.
