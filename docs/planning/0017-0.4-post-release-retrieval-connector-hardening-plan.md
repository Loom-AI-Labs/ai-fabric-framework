# ADR 0017 - AI Fabric 0.4 Post-Release Retrieval Connector Hardening

- **Status:** Implemented and verified
- **Date:** 2026-07-26
- **Target:** Next framework release after `0.4.0` (planned `0.5.0`)
- **Decision owner:** AI Fabric framework
- **Depends on:** AI Fabric `0.4.0`, ADR 0016 annotation/entity lifecycle hardening
- **Related:** ADR 0005 real-app expansion, Retrieval Connector Guide, 0.4 migration guide

## Decision Summary

Retain the retrieval connector as a read-only, documents-only `RAGProvider`, but harden its response
boundary before presenting it as a public live demo.

The connector must continue to return transient `RAGResponse.RAGDocument` evidence. It must not accept
or return `AIIndexDocument`, because `AIIndexDocument` belongs to AI Fabric's write/indexing lifecycle.

The hardening change will:

1. verify that returned documents belong to the requested and authorized vector space;
2. bound every externally supplied document field and the overall response;
3. validate and project metadata through an explicit allowlist;
4. validate URLs and scalar score values;
5. provide a fail-closed document sanitizer extension point;
6. preserve visible connector failures and diagnostics;
7. add packaged and real-boundary verification.

Existing valid documents-only responses remain structurally valid. Responses that rely on
cross-vector-space documents, unbounded fields, unsafe URLs, or arbitrary metadata will be rejected or
projected according to explicit policy.

## Context

AI Fabric `0.4.0` replaced the old annotation and indexing lifecycle with a typed, validated,
transaction-aware projection:

```text
application entity, migration row, trusted data-sync input, or Spring AI document
  -> compiled entity/indexing policy
  -> destination-specific projection
  -> AIIndexDocument
  -> durable queue
  -> embedding and vector provider
```

The retrieval connector is on the read side of the boundary:

```text
RAGRequest
  -> POST /retrieval/search
  -> external retrieval implementation
  -> documents-only response
  -> RAGResponse.RAGDocument
  -> AI Fabric context construction and answer generation
```

The current architecture is valid for `0.4.0`. The connector:

- implements the current `RAGProvider` contract;
- maps `RAGRequest.entityType` to the external `vectorSpace`;
- forwards the canonical verified `authContext`;
- rejects indexing and removal operations;
- requires documents-only responses;
- rejects top-level answers, prompts, messages, instructions, and tool calls;
- rejects malformed document arrays and responses containing only invalid documents;
- keeps generation inside AI Fabric.

Baseline verification before this hardening passed against the `0.4.0`
reactor:

- `ai-fabric-core`: 677 tests;
- `ai-fabric-retrieval-connector`: 17 tests;
- zero failures, errors, or skips in the focused run.

## Why `AIIndexDocument` Does Not Belong In This Protocol

`AIIndexDocument` is AI Fabric's versioned, immutable, class-free indexing work payload. It contains
only data approved by the compiled entity or ingestion projection:

- schema version and descriptor hash;
- stable entity type and entity id;
- work type and source operation;
- text intended for semantic search;
- text intended for RAG context;
- vector metadata;
- typed LLM context;
- API response metadata;
- source version, correlation id, and occurrence timestamp.

It is safe to persist in the durable indexing queue because it contains an approved projection rather
than a serialized application entity.

The retrieval connector does not create indexing work. It reads documents already selected by an
external search system. Its result therefore maps to `RAGResponse.RAGDocument`, which represents
transient evidence for the current request.

The contracts must remain separate:

| Contract | Direction | Lifetime | Purpose |
| --- | --- | --- | --- |
| `AIIndexDocument` | Application/ingress to indexing worker | Durable | Create, update, delete, or analyze indexed evidence |
| `RAGResponse.RAGDocument` | Retrieval provider to orchestration | Request-scoped | Supply evidence for grounding and client citation |

Requiring external connectors to return `AIIndexDocument` would expose internal queue semantics,
couple customer retrieval services to the indexing lifecycle, and confuse write authorization with
read authorization.

## Code-Backed Findings

### 1. Runtime Compatibility Is Proven

`RetrievalConnectorRAGProvider` implements both `performRag(...)` and `performRAGQuery(...)` using the
current `RAGRequest` and `RAGResponse` contracts. Auto-configuration contributes it only when:

- `ai.retrieval.connector.enabled=true`; and
- no application-owned `RAGProvider` already exists.

This remains compatible with the `0.4.0` orchestration pipeline and preserves application extension
ownership.

### 2. The Connector Is Correctly Read-Only

`indexContent(...)` and `removeContent(...)` fail explicitly. External retrieval owns its source data,
index, embedding process, update lifecycle, and delete lifecycle.

The connector must not silently route writes into the external retrieval API.

### 3. Documents-Only Validation Is Strong

Successful connector responses containing answer-generation or instruction fields fail with
`INVALID_RESPONSE`. Required document fields are:

- non-empty `id`;
- non-empty `content`;
- numeric `score`.

Malformed individual documents are skipped only when at least one valid document remains. A response
containing only invalid documents fails closed.

### 4. Returned Vector Space Was Not Verified

Before this change, the request sent one authorized vector space, but each returned document could
provide a different `vectorSpace`. The provider copied that value into document type and metadata
without checking it against the request.

The mandatory sanitizer now rejects the complete response with `VECTOR_SPACE_MISMATCH` before
generation whenever returned evidence conflicts with the requested space. An omitted document space
inherits the requested space.

### 5. Returned Metadata Was Structurally Unbounded

Before this change, the parser copied arbitrary string-keyed metadata into the returned RAG document.

External metadata is now projected through a deny-by-default dotted-path allowlist with entry, depth,
and serialized-size budgets. Reserved `_aifabric*` paths are always rejected. This policy is
independent of the `0.4.0` entity descriptor because the document came from an external read system,
not AI Fabric's indexing lifecycle.

### 6. External Field Bounds And URL Policy Were Missing

The response policy now enforces:

- maximum returned document count;
- id, content, source, URL, or vector-space lengths;
- total response/context character budget;
- metadata entry count, nesting depth, or serialized size;
- finite score values;
- safe URL schemes or host policy.

These were post-release hardening gaps, not reasons to replace the connector architecture.

## Required Design

### 1. Introduce A Retrieval Response Policy

Add typed properties under:

```yaml
ai:
  retrieval:
    connector:
      response-policy:
        max-documents: 50
        max-response-characters: 1000000
        max-document-id-characters: 512
        max-content-characters: 32000
        max-context-characters: 128000
        max-source-characters: 256
        max-url-characters: 2048
        max-vector-space-characters: 128
        max-metadata-entries: 32
        max-metadata-depth: 4
        max-metadata-characters: 8192
        max-message-characters: 512
        max-error-code-characters: 64
        allowed-url-schemes: [https]
        allowed-url-host-suffixes: []
        allowed-metadata-keys: []
        unknown-metadata-policy: DROP
```

These defaults are implemented, startup-validated, and documented.
Vector-space matching is mandatory and intentionally has no disable switch.

### 2. Enforce Vector-Space Ownership

For every returned document:

- if `vectorSpace` is absent, assign the requested authorized vector space;
- if it exactly matches the requested space after surrounding whitespace is
  removed, accept it;
- if it differs, fail the complete connector response with `VECTOR_SPACE_MISMATCH`;
- never silently relabel a conflicting returned value;
- record only bounded, non-sensitive mismatch diagnostics.

Failing the complete response prevents an apparently valid subset from hiding a connector isolation
defect.

### 3. Add Metadata Projection

Use a deny-by-default metadata policy for external documents:

- structural attribution fields such as `vectorSpace`, `source`, and validated `url` remain separate;
- nested metadata keys must be explicitly allowlisted;
- unknown keys are rejected or removed according to one documented policy;
- security-sensitive deployments use reject mode;
- metadata values must contain only bounded JSON-compatible values;
- reserved `_aifabric*` keys cannot be supplied by an external connector.

The default behavior must not imply that arbitrary connector metadata has passed the
`AIContextDestination.API_RESPONSE` projection.

### 4. Add A Sanitizer SPI

Introduce an application-extensible response boundary, provisionally named:

```java
public interface RetrievalDocumentSanitizer {
    RAGResponse.RAGDocument sanitize(
        RAGResponse.RAGDocument document,
        RetrievalDocumentSanitizationContext context
    );
}
```

Requirements:

- default implementation applies bounds, vector-space validation, URL policy, and metadata policy;
- applications may add PII or domain-specific sanitization;
- sanitizer failure terminates the retrieval response;
- no sanitizer may widen the requested vector space or restore removed metadata;
- sanitized output is the only document form used for context and API response.

### 5. Validate URLs

Accept only configured schemes, with `https` as the production recommendation.

- reject control characters and malformed URLs;
- optionally allow configured host suffixes;
- do not fetch connector-provided URLs;
- return URLs only as citation metadata;
- ensure UI clients treat them as untrusted external links.

### 6. Bound Scores And Response Size

- require finite numeric scores;
- keep provider-specific score scales, because the connector contract only requires monotonic ordering;
- reject `NaN`, positive infinity, and negative infinity;
- enforce that returned document count does not exceed the effective request `topK`;
- enforce a total context budget before constructing the RAG context;
- preserve response ordering after invalid-document rejection and sanitization.

Do not force all scores into `0..1` unless a future version introduces an explicit score-normalization
contract.

### 7. Preserve Authorization Defense In Depth

AI Fabric continues to send canonical `trace.authContext`.

The external connector must:

- authenticate AI Fabric through API key, HMAC, or a future stronger transport;
- authorize subject, tenant, customer, deployment, scopes, and vector space;
- apply requested metadata filters before returning evidence;
- return a structured denial rather than partial unauthorized documents.

AI Fabric must independently verify response vector-space ownership even when the connector is
authenticated.

### 8. Keep Failures Visible

Do not add deterministic content or local-vector fallback when:

- connector authentication fails;
- the connector is unavailable;
- a required response field is invalid;
- vector space mismatches;
- sanitization or metadata projection fails;
- response bounds are exceeded.

Return a stable error code and safe diagnostic metadata. Never include credentials, full connector
responses, document content, or raw authorization context in failure messages.

## Compatibility And Migration

The endpoint remains:

```text
POST /retrieval/search
```

The top-level request and response shapes remain unchanged.

Connector owners must review:

1. every returned document uses the requested vector space or omits it;
2. content and identifiers fit documented limits;
3. citation URLs use allowed schemes;
4. required metadata keys are configured in the allowlist;
5. no reserved AI Fabric metadata keys are returned;
6. the connector applies tenant and filter authorization before retrieval.

This hardening does not require:

- migrating to `AIIndexDocument`;
- adding annotation-driven entities to the AI Fabric application;
- exposing the customer's vector database to AI Fabric;
- changing the customer's internal indexing schema.

## Verification Plan

### Unit And Contract Tests

- valid documents-only response remains accepted;
- missing document vector space is normalized to the requested space;
- mismatched document vector space fails the whole response;
- unknown and reserved metadata keys follow configured policy;
- allowed metadata survives unchanged;
- oversized id, content, URL, vector space, metadata, and response count fail predictably;
- malformed and disallowed URL schemes fail;
- non-finite scores fail;
- generated-answer and prompt fields remain forbidden;
- connector denial remains a denial and is not retried unless its code is explicitly retryable;
- canonical auth context remains present and legacy identity fields remain absent;
- custom sanitizer can narrow output but cannot widen vector-space or metadata policy.

### Packaged Boundary Lab

Add the planned `retrieval-connector-boundary-lab` with:

- an AI Fabric application using `ai-fabric-retrieval-connector`;
- a small customer-owned retrieval fixture behind `POST /retrieval/search`;
- one valid documents-only response;
- one tenant/vector-space denial;
- one generated-answer injection response;
- one cross-vector-space response;
- one unsafe metadata/URL response;
- visible AI Fabric generation from accepted evidence only.

The deterministic smoke profile must use a clearly named local fixture. An opt-in live profile may use
a real LLM for generation, but retrieval remains customer-owned and documents-only.

### Release Gate

Run:

```bash
mvn -B -V --no-transfer-progress \
  -f ai-infrastructure-module/pom.xml \
  -pl ai-fabric-retrieval-connector -am \
  -DskipITs test
```

Then run the packaged boundary lab and prove:

- accepted evidence reaches generation;
- rejected evidence never reaches the prompt or client document panel;
- failures remain visible;
- no secret, raw auth context, rejected metadata, or document content appears in logs.

## Non-Goals

- Replacing `AIIndexDocument`.
- Adding write/index/remove operations to the retrieval connector.
- Letting external retrieval generate the final answer.
- Building multi-provider federation in this change.
- Automatically trusting connector metadata because the transport is authenticated.
- Hiding connector failures behind another retrieval provider.

## Completion Criteria

This post-release hardening item is complete when:

1. the response policy and sanitizer contracts are implemented and documented;
2. matching vector-space enforcement is fail-closed;
3. field, response, metadata, URL, and score bounds are covered by tests;
4. current valid connector responses remain supported with documented metadata configuration;
5. the boundary lab proves accepted and rejected paths through a packaged application;
6. release notes describe the stricter external retrieval boundary;
7. no code or documentation suggests that `AIIndexDocument` is a retrieval response type.
