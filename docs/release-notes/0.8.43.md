# AI Fabric 0.8.43

## Conversation Context Handoff

This focused patch preserves conversational references between intent extraction,
READ planning, retrieval and answer generation. Previously, extraction could see
the preceding exchange while later planner/generation calls could not. A follow-up
comparison could consequently search an unresolved phrase or answer from unrelated
records despite having an owner-authorized conversation.

- The READ planner receives bounded native user/assistant history and existing
  active target references, retaining their original trust and origin.
- The planner may return an optional, self-contained `retrievalQuery`. Retrieval
  uses that explicit model decision and records its source in diagnostics. The
  original user query is unchanged; deterministic code does not infer names or
  rewrite references by matching phrases.
- RAG, read-evidence and generation-only answers receive bounded native history
  through the existing generation-message contract. History is not packed into
  the current evidence prompt or silently discarded on a text-only retry.
- Prior messages explain references, not freshness or authority. Current
  authorized evidence takes precedence; older statements must be attributed as
  historical where relevant. Transcript text cannot grant ownership, hidden IDs,
  new actions or retrieval permissions.

## Bounds And Diagnostics

The existing `read-action-resolution.max-planner-context-chars` budget bounds
the additional planner conversation/target projection and native generation
history. Recent messages are retained first. Truncation is explicit in
`readActionResolution.conversationContext` and
`responseGenerationConversationContext`; these contain counts, not transcript
content. The model-authored retrieval query is exposed in the existing debug
metadata together with `retrievalQuerySource=MODEL`.

Conversation ownership, canonical tenant/deployment binding and user/assistant
roles are validated before history is projected. Unbound requests and
`ConversationPersistencePolicy.NEVER` do not resurrect history. Caller-supplied
metadata is not an alternative history store. Empty or failed conversation-bound
generation remains a visible failure rather than retrying without its history.

No database migration, new fact ledger, source-data migration or reindexing is
required. No automatic source fan-out, target activation, action execution or
semantic text matching is added. Missing optional planner query output is not
a new hard validation failure. No-history behavior retains its existing path.

## Adoption And Scope

Upgrade the BOM and all framework dependencies consistently to `0.8.43`, rebuild
the consumer and use its existing conversation binding. Direct Java users of the
internal `ResolutionOutcome` record must account for the optional retrieval-query
field; its existing factory methods retain their signatures.

This release preserves the published0.8.42 baseline and main's subsequent demo,
documentation and fixture corrections. The unrelated dirty indexing/execution
worktree is not included. Compound-delivery completeness and application-specific
policy interpretation are separate issues, not claimed fixes here.
