# AI Fabric 0.8.54

## Scope

A completed READ-planner `ANSWER_FROM_CONTEXT` decision can now retain a genuinely
history-only informational continuation instead of being forced into indexed
retrieval by a cooperation policy. This applies only when extraction explicitly
requires no retrieval, owned conversation context is available, no current
target/attachment/transient input exists, and there is no executed, rejected,
deduplicated or unfinished READ work whose recovery must be preserved.

Conversation history remains historical reference, not new grounding evidence,
current system state, permission or a trusted action identifier. Explicit fresh
retrieval, actual READ execution and failed/insufficient evidence retain their
existing policy and authorization checks. No message matcher, fabricated answer,
silent model retry or new action authority is introduced.

The READ planner's source catalogue now describes when parallel cooperation also
requires indexed evidence after a READ. Its instructions distinguish authorized
indexed namespaces from action/source identifiers and request the relevant
source on that existing path. Context-only plans do not require needless tools.
Extraction guidance likewise distinguishes transforming earlier content from
requests requiring fresh evidence.

Routing-terminal results retain the READ planner's diagnostics and safe executed
READ receipts, without replacing their original failure status or exposing
private invocation parameters/internal pinned-target fields in public JSON.

## Adoption

There is no new configuration property, migration or reindex requirement.
Existing cooperation, retrieval, confirmation and recovery settings remain in
effect, including the opt-in recovery introduced in 0.8.53. Rebuild and deploy
consumers; changing a source dependency does not upgrade a running application.
