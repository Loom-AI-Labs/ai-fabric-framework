# AI Fabric `0.8.9`

- **Release date:** 2026-10-04
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.9`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.9` preserves the bounded target working set produced by successful
read-action resolution so chat-session consumers can resolve a natural follow-up
such as "of those" on the next turn.

## Fixed

- Successful read actions used for grounded generation now carry their pinned
  targets through an internal orchestration field to the conversation recorder.
- The chat-session module persists those targets through its existing bounded,
  server-owned `lastResolvedTargets` contract.
- Targets from multiple successful read actions are deduplicated by vector space
  and target ID before persistence.
- Failed action results do not update the conversation working set.
- Public `data.actions[]` projections remain unchanged and do not expose pinned
  target IDs, target content, or target metadata.
- The internal carrier is transient, excluded from equality/to-string output,
  and ignored by JSON serialization.

The implementation is action- and domain-neutral. It does not inspect action
names, target text, user wording, or application-specific fields.

## Migration

Consumers must upgrade the BOM and all AI Fabric artifacts together to `0.8.9`.
No compatibility mode or parallel old/new runtime is required.

Chat deployments that use cross-turn action-result continuity must keep the
existing chat-session pinned-target persistence capability enabled. Applications
that do not use chat sessions or read-action resolution are unaffected.
