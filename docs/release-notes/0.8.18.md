# AI Fabric `0.8.18`

- **Release date:** 2026-10-10
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.18`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.18` makes intent-provider failure truthful for every
orchestration purpose. A hosted conversational canary found that an exhausted
provider could be converted into a successful `OUT_OF_SCOPE` response after
the bounded extraction ladder failed. That hid an operational outage as a
domain rejection.

The release also updates the Google embedding contract after the retirement of
`text-embedding-004`. Gemini embeddings now default to
`gemini-embedding-2` and send an explicit, configurable output dimension so
the provider response remains aligned with the vector-store schema.

## Fixed

- Conversational, specialist, and other model-directed requests now terminate
  with a sanitized `ERROR` when bounded intent extraction cannot produce a
  valid result.
- Provider failures use the stable `INTENT_PROVIDER_FAILED` code and are marked
  retryable in pipeline diagnostics.
- Non-provider extraction failures use `INTENT_EXTRACTION_FAILED` and remain
  non-retryable.
- A genuine `OUT_OF_SCOPE` intent produced successfully by the model remains a
  normal, successful result; only failed extraction loses the old synthetic
  fallback.
- The framework's default out-of-scope guidance is application-neutral rather
  than commerce-specific.
- Gemini embeddings default to `gemini-embedding-2` with 768 dimensions.
  `ai.providers.gemini.embedding-dimensions` can select another supported
  positive dimension when the vector store is provisioned to match it.

## Security And Compatibility

- Provider exception details and credentials are not projected to clients.
  The outward response contains only the stable code and sanitized public
  message.
- Access, action authorization, confirmation, retrieval, and compound-evidence
  behavior are unchanged.
- Applications that treated a synthetic `OUT_OF_SCOPE` response as provider
  availability evidence must instead handle the explicit retryable error.

## Migration

Import the `0.8.18` BOM and upgrade every AI Fabric artifact together. No
database migration is required. Existing Gemini deployments using a different
model or dimension must rebuild derived vector indexes when adopting the new
model/dimension contract; deployments retaining an explicit unchanged
embedding contract do not need to reindex.

Operators should alert on `INTENT_PROVIDER_FAILED` and inspect provider quota,
credentials, endpoint health, and model availability before retrying.

## Verification

- conversational and specialist provider-failure termination
- sanitized stable error code and retryability metadata
- successful model-produced `OUT_OF_SCOPE` regression coverage
- current Gemini embedding model and explicit output-dimension coverage
- complete core, release-reactor, and real-app gates
