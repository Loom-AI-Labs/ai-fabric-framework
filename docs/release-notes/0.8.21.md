# AI Fabric `0.8.21`

- **Release date:** 2026-10-10
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.21`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.21` adds a bounded structured-input path for continuing an
existing governed action draft. A user-facing form can now preserve exactly
the values typed by the user without asking an LLM to recover those values
from generated prose and a long conversation history.

## Added

- `ActionDraftSubmission` carries one action name and bounded JSON-compatible
  public parameter values for the current request.
- `OrchestrationContext.actionDraftSubmission` makes that payload available to
  the existing action-draft continuation pipeline without serializing it into
  context or diagnostics.
- A matching submission is converted deterministically into the continuation
  intent. The semantic LLM continuation analyzer remains the fallback for
  ordinary conversational replies.
- Structured values participate in ordinary user-evidence provenance checks,
  while trusted application evidence remains a separate boundary.
- Diagnostics identify the input source and parameter names without exposing
  submitted values.

## Security Boundary

Structured input is untrusted user input, not trusted execution context. It is
accepted only when an open action draft exists and the submitted action matches
that draft. Unknown, internal, secret, system-owned, or otherwise non-user-
visible top-level fields are rejected. Nested values are sanitized against the
declared action schema.

All normal schema validation, provenance checks, application policy,
confirmation, and governed execution still apply. Evidence-bound resource IDs
must still match trusted attachment, target, or application evidence; including
an ID in this payload does not make it trusted.

The payload is bounded by action length, parameter count, string length,
collection size, supported JSON-compatible scalar types, and nesting depth. Its
`toString()` representation includes parameter names but never values.

## Application Integration

Map an explicitly declared public request field to the orchestration context:

```java
OrchestrationContext.builder()
    .actionDraftSubmission(request.getActionDraftSubmission())
    .build();
```

Clients should submit both a human-readable query for conversation history and
the exact form payload:

```json
{
  "query": "Continue with the details I entered.",
  "conversationId": "conversation-123",
  "actionDraftSubmission": {
    "action": "request_callback",
    "parameters": {
      "name": "Customer Name",
      "phone": "+44 7700 900000"
    }
  }
}
```

Applications must not copy this object into generic metadata or trusted
execution context. They should map it directly from a typed request DTO.

## Migration

Import the `0.8.21` BOM and upgrade every AI Fabric artifact together. Add the
typed request mapping only where an application exposes action-draft forms. No
database migration, embedding change, or reindex is required.

## Verification

- exact structured values continue an open draft without an LLM call
- action mismatch and hidden-field submissions fail closed
- nested values are schema-sanitized and bounded
- submitted values remain untrusted user evidence
- trusted-resource and confirmation boundaries remain unchanged
- complete core, release-reactor, real-app, and external-consumer gates
