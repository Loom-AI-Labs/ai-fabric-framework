# AI Fabric `0.8.35`

- **Release date:** 2026-10-16
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.35`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.35` is the release-integrity successor to `0.8.34`. It contains
the same reviewed canonical conversation-state implementation and corrects the
coding-assistant skill validator so it derives the supported immutable release
from `SKILL.md` and verifies it against the framework BOM. This prevents future
release metadata from becoming detached from the published framework version.

## Canonical Conversation State

- Controlled conversations can bind pending confirmations, action drafts, and
  working targets to the canonical tenant-, deployment-, owner-, and
  conversation-scoped control record.
- The host must construct the binding from trusted authenticated context.
  Public request fields cannot select canonical storage.
- Mutations require the expected control epoch and an `AI_ACTIVE` conversation.
  Stale turns, replayed confirmations, and concurrent stack changes fail closed.
- Legacy `chat_sessions` writes use owner-verified atomic mutation and
  optimistic row versioning, preventing stale detached saves from restoring
  consumed state.
- Requests without a canonical binding retain the existing legacy
  chat-session behavior.

## Required Host Migration

Before enabling canonical conversation state, hosts must:

1. add `ai_conversation_orchestration_state`, keyed by tenant, deployment, and
   conversation with owner, revision, JSON state, timestamp, and a cascading
   foreign key to `ai_conversation_control`;
2. add `chat_sessions.row_version BIGINT NOT NULL`, initializing existing rows
   to `0` when the legacy table is retained;
3. construct `ConversationStateBinding` only after authenticated conversation
   resolution and AI-turn lease acquisition; and
4. advertise the migration and capability through deployment readiness before
   enabling controlled-conversation products.

No vector reindex, prompt change, provider configuration change, or model
retest is required.
