# AI Fabric `0.8.30`

- **Release date:** 2026-10-12
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.30`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.30` keeps the strict governed action-parameter validation added
in `0.8.29` and corrects the ownership boundary for confirmation-interceptor
guards. Framework control state is now stored separately from business action
parameters, so resumed actions receive only fields declared by their action
contract.

## Confirmation-Interceptor State

- `PendingAction` has typed `confirmationInterceptorGuards` state for
  once-only interception controls.
- Annotation-driven, configured, and core confirmation interceptors all read
  and write that state instead of adding private marker keys to
  `actionParams`.
- Pending-action persistence round-trips the guard state independently from
  trusted resolved parameters and business parameters.
- Interceptor guard names are normalized as exact structured identifiers; no
  user-message matching or semantic fallback is involved.
- `ConfirmationInterceptionContext` exposes explicit guard helpers. The old
  parameter-named helpers delegate to the separated state and are deprecated.

## Action Validation Remains Strict

Unknown model, client, planner, or resolver-authored action fields are still
rejected. This release does not permit underscore-prefixed fields, silently
drop unknown values, clamp parameters, or weaken declared schemas. The fix is
to keep framework-owned state out of the action payload before validation.

## Read Actions And Evidence Domains

Read actions remain independent from vector storage by default. They may fetch
live, operational, or non-grounding entities without declaring
`groundingVectorSpaces`. If that optional metadata is present, its exact
evidence-domain constraint remains enforced.

## Migration

Use the `0.8.30` BOM for every AI Fabric artifact. Applications using
confirmation interceptors should not adopt `0.8.29`: a once-only guard could
be carried into a resumed action and correctly rejected as an unknown business
parameter. No database migration, vector reindex, action-contract change, or
deployment configuration change is required.

## Verification

- action parameter type, bounds, allowed-value, pattern, object, array, and
  unknown-field enforcement remains covered at extraction, planner, and final
  invocation boundaries;
- configured and annotation-driven interceptor tests prove guards never enter
  action parameters;
- pending-action storage proves trusted parameters and interceptor guards
  survive independently;
- the retention scenario proves both accepting a discount and rejecting it to
  execute the original cancellation; and
- the complete deterministic P1 real-app scenario gate passes.

The relationship-query module is unchanged and remains outside this release's
correction claim.
