# AI Fabric `0.7.0`

- **Release date:** 2026-09-19
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.7.0`
- **Upgrade baseline:** `0.6.1`
- **Java:** 21
- **Spring Boot:** 4.1.x
- **Primary proofs:** `incident-investigation-room`,
  `agentic-ai-action-resolver`, and `agentic-execution-consumer`

AI Fabric `0.7.0` adds official declarative bounded specialist-chain
manifests. Applications and managed platforms can now compose a reviewed,
exact-version team of existing read-only specialists in immutable YAML/JSON
without introducing a private workflow language or a second execution engine.

## What Changed

### `SpecialistChain` execution resources

The existing `ai.fabric/v1` resource bundle now accepts
`kind: SpecialistChain`. A resource declares:

- an exact JSON Schema-backed chain request;
- one exact manager specialist;
- a closed ordered list of exact read-only, non-interactive workers;
- bounded RFC 6901 input mapping;
- bounded summary, string-fact, and approved-evidence projection;
- delegation, parallel, and terminal-handoff eligibility;
- chain budgets; and
- conversation policy.

The compiler produces the existing `SpecialistChainDefinition<JsonNode>`.
Java-defined and manifest-defined chains share one source-aware registry,
duplicate detection, gateway, authorization path, JDBC state, replay,
recovery, cancellation, metrics, and failure model.

The resource cannot reference Java classes, Spring beans, adapters, mappers,
projectors, expressions, scripts, SQL, providers, credentials, or trusted
identity. If mapping or projection needs authoritative application logic, the
chain remains Java-defined.

### Bounded mapping and projection

Declarative mapping:

- selects only declared chain-input values or the manager objective;
- writes only top-level destination fields into a fresh JSON object;
- preserves scalar, object, and array types without coercion;
- validates the complete mapped object against the worker input schema; and
- enforces pointer, mapping, depth, node-count, value-byte, serialized-byte,
  and cumulative-work ceilings.

Declarative projection validates worker output against its pinned schema and
exposes only the declared string summary, bounded string facts, and optional
approved evidence IDs. Missing, invalid, or oversized data fails visibly; raw
worker output is withheld and synthesis does not continue.

### Exact source and content identity

Registrations now record whether a chain is Java- or manifest-defined.
Manifest registrations preserve three identities:

- complete audit resource hash;
- executable declarative-semantics hash; and
- effective execution hash covering resolved schemas, manager, workers,
  ordered targets, mappings, projections, limits, and policy.

Descriptive metadata may change the audit identity without silently changing
execution identity. Any executable or resolved-dependency change invalidates
protected replay.

### Offline authoring and operations

New public support includes:

- `SpecialistChainManifestValidator` for candidate validation and published
  exact-version semantics comparison;
- `SpecialistChainAuthoringCatalogProvider` for bounded trusted authoring UI;
- `SpecialistChainManifestRuntimeStatus` for safe counts, aggregate hashes,
  readiness, and diagnostics;
- the published `specialist-resource-v1.schema.json` chain definition; and
- Micrometer load, compilation, mapping, projection, and registry metrics.

A discovered chain resource while chain execution is disabled is never
silently ignored. Fail-fast startup rejects it; diagnostics mode reports it as
inactive and not ready without creating a JDBC requirement.

### Reference applications

Incident Investigation Room packages
`incident-declarative-investigation@1`, proving a complete config-defined
parallel/adaptive read-only investigation and exact durable replay.

Agentic AI Action Resolver intentionally keeps its rich
`account-smart-resolution@1` Java chain and adds
`account-declarative-resolution@1`. This demonstrates the boundary: the
manifest path handles ordinary schema-backed mapping/projection, while the
Java path retains computed authoritative application facts.

The standalone `agentic-execution-consumer` compiles a packaged chain using
only public `ai-fabric-execution` APIs.

## Compatibility And Migration

This is a feature release. Existing applications do not need to convert Java
chains to YAML. Manifest chains are opt-in and chain execution remains disabled
by default.

One intentional identity migration applies to existing chains: target
declaration order is now preserved in the content hash. `0.6.x` sorted targets
while hashing even though manager input and execution retained declaration
order. Java chains declared in non-sorted order therefore receive a new hash.

Before upgrading a chain-enabled `0.6.1` deployment:

1. Stop new chain submissions.
2. Drain or cancel non-terminal chain executions.
3. Do not rewrite stored hashes or relabel old checkpoints.
4. Keep the JDBC state and stable protection secrets through retention.
5. Upgrade with chains disabled and run existing regressions.
6. Enable one reviewed declarative canary only after storage, secrets, exact
   hashes, keyed-provider behavior, replay, restart, and isolation pass.

Use the full
[LoomAI 0.7 migration runbook](../Framework-Dev-Guides/application-patterns/LOOMAI_AI_FABRIC_0_7_DECLARATIVE_CHAIN_MIGRATION_RUNBOOK.md).

## Configuration

```yaml
ai:
  execution:
    manifests:
      enabled: true
      fail-fast: true
      locations:
        - classpath*:ai-specialists/*.yml
        - file:/etc/ai-fabric/*.yml
    specialist-chains:
      enabled: true
      durable-enabled: true
      allow-ephemeral: false
      initialize-schema: false
      max-json-pointer-characters: 500
      max-json-pointer-depth: 16
      max-mappings-per-target: 32
      max-mappings-per-chain: 128
      max-copied-node-depth: 16
      max-copied-node-count: 1000
      max-copied-value-bytes: 32768
      max-mapped-input-bytes: 65536
      max-mapping-work-units: 4096
      encryption-secret: ${AI_SPECIALIST_CHAIN_ENCRYPTION_SECRET}
      fingerprint-secret: ${AI_SPECIALIST_CHAIN_FINGERPRINT_SECRET}
```

Production uses an application-owned Flyway/Liquibase migration for the
existing `ai_specialist_chain_execution` table and keeps
`initialize-schema=false`. No second chain state store is introduced.

## Verification

Pre-publication verification covers:

- an isolated 36-module framework `clean verify` with the real local ONNX
  model: 1,947 tests, zero failures, zero errors, and three intentional skips;
- an isolated 26-module real-app `clean verify`: 531 tests, zero failures, zero
  errors, and 23 credential-gated skips;
- all 417 focused `ai-fabric-execution` tests and all five standalone public
  consumer tests;
- strict parser/schema/compiler, exact hash, bounded mapping/projection,
  mixed-source registration, duplicate rejection, and disabled-feature tests;
- JDBC restart, replay, cancellation, definition-drift, and isolation tests;
- all 15 keyed Incident Investigation Room OpenAI scenarios, including
  manifest-defined parallel execution and exact replay; and
- a packaged Docker candidate using PostgreSQL that discovered one manifest
  chain, executed and replayed it, restarted, and replayed the same durable
  result without re-execution.

Post-publication verification must additionally prove the immutable tag,
Maven Central publication, clean-cache external consumption, deployed demo
version/commit identity, and live declarative endpoint behavior. Exact counts
and workflow evidence are recorded after those gates complete.

Tests run normally. Provider-credential and external-service cases remain
explicit keyed/manual evidence; no deterministic fallback is accepted as a
real-provider pass.

## Scope

`0.7.0` does not add arbitrary graphs, recursion, nested chains, dynamic target
discovery, write-capable workers, executable configuration, partial-success
fan-in, hot manifest mutation, provider selection in YAML, or exactly-once
provider invocation.
