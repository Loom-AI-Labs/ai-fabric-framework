# AI Fabric `0.8.29`

- **Release date:** 2026-10-12
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.29`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.29` prevents model-authored action parameters from reaching an
action handler when they violate the registered action contract. Invalid
parameters now produce typed validation evidence and, where bounded iterative
planning is enabled, a model-driven repair opportunity.

## Action Parameter Contract Enforcement

- Intent extraction validates model-provided action parameters against their
  registered type, allowed values, pattern, numeric bounds, object properties,
  array item schema, and bounded structural limits.
- A contract failure is reported as `ACTION_PARAMETER_CONTRACT_INVALID` and is
  treated as incomplete structured output, allowing the configured progressive
  extraction strategy to ask the LLM for a corrected structure.
- The final governed invocation boundary repeats validation before any handler
  authorization or execution. Paths that bypass extraction therefore still
  fail closed.
- Existing untyped internal resolver fields and explicitly open object or array
  schemas remain supported. The framework enforces declared constraints and
  generic size limits without inventing constraints absent from the contract.

## Read-Action Planner Repair

- Planner proposals with missing or out-of-contract parameters are rejected
  before execution and recorded in diagnostics.
- In iterative mode, a rejected proposal triggers the next bounded planner
  iteration even when the previous model response incorrectly declared that no
  further step was needed.
- The next planner call receives the typed rejection, including the action,
  field path, reason, and rejected parameters, so the LLM can author a valid
  replacement.
- If the repair budget is exhausted, the framework executes no invalid action.
  Retrieval may proceed only when the deployment's explicit RAG cooperation
  policy already permits it.

## Read Actions And Evidence Domains

Read actions remain independent from vector storage by default. They may fetch
live, operational, or non-grounding entities without declaring
`groundingVectorSpaces`. When that optional metadata is present, its exact
evidence-domain constraint remains enforced.

## Philosophy And Safety

This release adds no natural-language matching, phrase rules, value clamping,
parameter dropping, domain-specific routing, or deterministic substitution for
an LLM decision. The framework validates declared contracts and security
boundaries. The LLM remains responsible for producing corrected semantic and
structured output within the configured retry budget.

## Migration

Upgrade all AI Fabric artifacts through the `0.8.29` BOM. No database migration,
vector reindex, action metadata change, or deployment configuration change is
required. Actions benefit from stronger validation when their existing
parameter schemas declare concrete constraints.

## Verification

- extraction rejects an out-of-range model-authored parameter as typed,
  repairable structured output;
- the final governed invocation rejects the same parameter before calling its
  handler;
- iterative read-action planning rejects `limit=50`, supplies the typed failure
  to a second model iteration, accepts `limit=10`, and executes exactly once;
- trusted runtime parameters, pending confirmations, open payload contracts,
  and internal resolver fields remain compatible; and
- the complete `ai-fabric-core` suite passes with 800 tests.

The relationship-query module is unchanged and remains outside this release's
correction claim.
