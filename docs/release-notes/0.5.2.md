# AI Fabric `0.5.2`

- **Release date:** 2026-07-31
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.5.2`
- **Compatibility baseline:** `0.5.1`

This security patch preserves server-verified identity boundaries when a
specialist invokes AI Fabric retrieval through `ai-fabric-execution`.

## Security Boundary Correction

`DefaultAIExecutionGateway` now treats identity and authorization metadata as
server-owned:

- adapter-supplied subject, tenant, deployment, caller, and scope values are
  removed;
- canonical values are rebuilt from `TrustedExecutionContext`;
- verified boundaries are propagated into orchestration and RAG requests; and
- unrelated application metadata remains available to the specialist.

This prevents a specialist input adapter or caller-controlled metadata from
weakening tenant- or deployment-scoped retrieval.

The protected metadata includes subject identity and type, authentication mode,
caller type, issuer, audiences, expiration, deployment, customer, tenant,
granted scopes, and requested scopes. Values not present in the trusted
execution context remain absent rather than falling back to caller input.

## Upgrade Guidance

Upgrade to `0.5.2` before enabling a specialist that combines:

- `ai-fabric-execution`;
- trusted tenant or deployment context; and
- RAG or retrieval-connector evidence.

The public indexing-status API introduced in `0.5.1` is unchanged. Applications
using only that API are not affected by this specialist retrieval defect.

If a LoomAI deployment must temporarily remain on `0.5.1`, disable the new
deployment-knowledge specialist explicitly:

```bash
LOOMAI_DEPLOYMENT_KNOWLEDGE_SPECIALIST_ENABLED=false
```

Do not enable that specialist on `0.5.1`.

## LoomAI Adoption

For the intended LoomAI release:

1. resolve all AI Fabric artifacts from Maven Central at `0.5.2`;
2. rebuild the runtime without locally installed framework artifacts;
3. verify the packaged runtime contains `ai-fabric-execution-0.5.2.jar`;
4. deploy the rebuilt runtime;
5. run two-tenant retrieval canaries for both tenant and deployment isolation;
6. verify missing-scope and missing-tenant requests fail closed;
7. verify provider failure remains visible and does not trigger a fallback; and
8. run the full platform release-readiness workflow.

No intermediate `0.4.x` or `0.5.0` deployment is required.

## Verification

Regression coverage proves that:

- trusted subject, tenant, deployment, and granted scopes replace spoofed
  adapter metadata;
- unsupported spoofed identity fields are removed;
- non-security application metadata is preserved; and
- existing core, conversation, execution, and specialist behavior remains
  unchanged.

The external deployment-knowledge canary must still be repeated against the
published `0.5.2` artifacts and deployed LoomAI runtime.
