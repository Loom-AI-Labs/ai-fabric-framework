# AI Fabric `0.8.20`

- **Release date:** 2026-10-10
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.20`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.20` closes a target-availability gap in model-selected read
actions. A grounding-eligible read action whose required identifier can only be
resolved from trusted attachment context could be selected for a broad
information request even when no current target existed. That produced an
internal-identifier clarification and could prevent a compound request from
returning otherwise available evidence.

## Fixed

- Prompt-visible metadata now tells the intent model when a grounding read
  requires trusted current-target context and directs it to retrieval or a
  search action when that context is absent.
- A deterministic post-extraction guard converts an unavailable target-bound
  grounding read into a normal information obligation.
- The fallback preserves the model's vector space when present, otherwise it
  uses the action's sole declared grounding space, and remains bounded by the
  existing deployment allowlist and retrieval policy.
- Conversion is limited to `READ`, grounding-eligible actions whose missing
  required parameters are non-user-visible, evidence-bound, and resolved from
  `ATTACHMENT_METADATA`.
- Writes, mixed read/write actions, visible required parameters, owned-resource
  resolution, read-action resolvers, and requests that explicitly require
  target resolution retain their existing behavior.
- Normalization diagnostics record
  `COERCE_UNAVAILABLE_TARGET_BOUND_READ_TO_INFORMATION` when the guard is used.

## Security And Compatibility

The correction does not accept an identifier from model output or public
request context. Trusted target parameters remain application-owned and
evidence-bound. The resulting information obligation still passes through
vector-space validation, deployment allowlists, source isolation, and normal
RAG/read-action planning.

This is a compatible patch for correctly declared action contracts. An action
that relies on attachment context must declare the relevant parameter as
required, `askUser=false`, `evidenceBound=true`, and resolve it from
`ATTACHMENT_METADATA`.

## Migration

Import the `0.8.20` BOM and upgrade every AI Fabric artifact together. No
database migration, embedding change, or reindex is required. Review
grounding-eligible detail/read actions to ensure trusted target parameters use
the structured parameter contract rather than relying only on prose.

## Verification

- target-bound read without a current target becomes information retrieval
- target-bound read with explicit target resolution remains an action
- write and read/write actions are never converted
- owned-resource and user-visible required parameters retain normal handling
- action catalogue exposes the trusted-target requirement without exposing the
  hidden identifier
- complete core, release-reactor, real-app, and external-consumer gates
