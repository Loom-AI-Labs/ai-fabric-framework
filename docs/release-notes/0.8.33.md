# AI Fabric `0.8.33`

- **Release date:** 2026-10-15
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.33`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.33` adds a deterministic authentication-requirement contract
for anonymous callers that select an action requiring a verified end-user
identity. It does not add an identity provider, login UI, or automatic replay.

## Structured Authentication Requirement

- Anonymous invocation of a registered action whose metadata has
  `anonymousAllowed=false` still fails closed before handler validation or
  execution. Unknown actions and registrations with missing metadata remain
  canonical `ACTION_NOT_FOUND` failures and never request authentication.
- The denied result now carries error code `AUTHENTICATION_REQUIRED` and an
  `ai-fabric-authentication-requirement-v1` payload containing the selected
  action and required `END_USER` subject type.
- Hosts can map this provider-neutral result to their own authentication UX
  without matching human-readable messages.
- Compound results promote an exact authentication requirement to the top
  level while retaining every child result, so a successful sibling cannot
  hide a protected capability's sign-in requirement.
- Authenticated callers for complete registrations, anonymous-allowed actions,
  and denials from an application's own authorization policy retain their
  existing behavior.
- The framework does not retry the blocked action. After authentication, the
  user must explicitly submit a new request.

## Migration

Adopt the `0.8.33` BOM consistently. No database migration, vector reindexing,
or provider configuration change is required. Hosts that offer anonymous chat
with protected capabilities may optionally consume the new structured result
to start their configured sign-in flow. Existing hosts that do not consume it
continue to receive the ordinary failed `ACTION_DENIED` result.

## Verification

- anonymous action-policy tests prove the structured requirement is emitted
  only for registered protected actions, that unknown or incomplete
  registrations do not trigger sign-in, and that the handler is not validated
  or executed;
- compound-normalization tests prove mixed successful and protected outcomes
  preserve the exact typed and serialized authentication contract;
- the framework release guards and mandatory deterministic release matrix are
  applied before publication;
- external consumer and packaged real-app gates are applied to the release
  candidate; and
- no real-provider gate is required because this patch changes neither model
  prompts nor model-selected intent/action extraction.
