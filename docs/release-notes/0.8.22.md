# AI Fabric `0.8.22`

- **Release date:** 2026-10-11
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.22`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.22` makes natural-language semantic decisions model-driven and
makes every permitted recovery explicit. Runtime code no longer repairs model
meaning through query keywords, phrase regular expressions, lexical overlap,
query-shape heuristics, or built-in moderation words. Configuration constrains
authority; it does not silently invent relevance or intent.

## Semantic Decision Contract

- Intent prompts and provider-native schemas now request complete obligation,
  target, retrieval, action, uncertainty, and clarification fields.
- Progressive extraction preserves the original structured result, reports
  typed validation issues, performs only bounded model repair, and returns an
  honest typed failure or clarification when repair is exhausted.
- The synthetic successful intent fallback is removed.
- Unknown actions and action/evidence-domain mismatches remain rejected unless
  the effective server-owned recovery policy explicitly permits a replan or
  bounded RAG path.
- Semantic diagnostics expose the original source/value, validation status,
  effective policy, recovery attempt, effective outcome, and bounded model-call
  count without exposing prompts or private reasoning.

## Retrieval And Evidence

- Vector-space routing no longer selects a source by matching query words to a
  vector-space name.
- An allowlist is an authority ceiling, not evidence that every listed source
  is relevant. Missing model selection clarifies by default.
- `DETERMINISTIC_RAG_GENERATE` may require retrieval and generation, but it no
  longer treats that execution mode as permission to choose a knowledge
  source.
- A single allowed vector space is not treated as relevant merely because it
  is the only member of an allowlist, including after an insufficient read
  action.
- Optional missing-source fan-out requires
  `BOUNDED_ALLOWED_FAN_OUT`, an enabled fan-out capability, a strict maximum,
  and an allowlist where the deployment requires one.
- Compound evidence preserves provider-ranked order and provider scores within
  each obligation. Bounded round-robin interleaving may preserve compound
  coverage, but orchestration no longer invents lexical relevance scores or
  query-matched excerpts.
- Advanced RAG is selected by structured model output or an explicit server
  mode, never query length or punctuation.
- Advanced-RAG provider failure is an explicit typed failure. It does not
  silently downgrade to basic RAG. Optional no-evidence broadening requires
  the named recovery policy and the same explicit positive fan-out bound.

## Safety And Provider Recovery

- Content moderation now uses typed moderation providers. Failure denies by
  default; a second provider is attempted only when explicitly configured.
- Generation and embedding failover are disabled by default and require an
  ordered named provider chain plus matching nonblank data-policy labels.
- Custom provider identifiers remain custom identifiers. Unknown names are no
  longer silently replaced with OpenAI generation defaults or ONNX embedding
  defaults.
- Embedding failover additionally requires matching embedding-compatibility
  groups. Equal dimensions alone are not treated as vector-space compatibility.
- Provider diagnostics record attempts and original/effective providers while
  redacting native exception details.

## Example And UI Boundaries

- Deterministic demo LLMs can run only under an explicit smoke/test posture;
  production startup requires a real provider.
- AI Workspace request construction now strips client-supplied semantic and
  authority fields. Explicit UI category selection remains bounded structured
  context, while attachment presentation cannot change runtime mode, position,
  vector space, action, or authority.
- Presentation-only text matching remains allowed and is verified separately
  from runtime semantics.

## Configuration

Strict recovery is the default. A deployment may opt into a bounded recovery
at the global or curated-mode level:

```yaml
ai:
  orchestration:
    semantic-recovery:
      extraction-failure: LLM_REPAIR_THEN_FAIL
      missing-target: LLM_REPAIR_THEN_CLARIFY
      missing-vector-space: LLM_REPAIR_THEN_CLARIFY
      invalid-vector-space: LLM_REPAIR_THEN_FAIL
      unknown-action: LLM_REPAIR_THEN_FAIL
      action-domain-mismatch: DENY_AND_LLM_REPLAN
      advanced-no-evidence: RETURN_NO_EVIDENCE
    modes:
      bounded-discovery:
        semantic-recovery:
          missing-vector-space: BOUNDED_ALLOWED_FAN_OUT
        rag:
          fanout-enabled: true
          max-spaces: 2
          retrieval-vector-spaces-allowlist: [product, policy]
```

`BOUNDED_ALLOWED_FAN_OUT` and `BOUNDED_ALLOWED_SPACE_RECOVERY` are inactive
unless the effective mode also sets `rag.fanout-enabled: true` and a positive
`rag.max-spaces`. Merely naming a recovery policy is not an unbounded search
instruction.

Provider fallback now requires all relevant contracts:

```yaml
ai:
  providers:
    enable-fallback: true
    generation-fallback-providers: [azure]
    embedding-fallback-providers: [azure]
    provider-data-policies:
      openai: customer-data-eu
      azure: customer-data-eu
    embedding-compatibility-groups:
      openai: catalog-embedding-v1
      azure: catalog-embedding-v1
```

## Migration

Upgrade all AI Fabric artifacts through the `0.8.22` BOM. Remove any
application assumption that a missing vector-space result automatically means
"search every allowed source." Keep strict defaults, or configure a named
bounded recovery deliberately. If provider fallback is enabled, configure the
ordered providers and both compatibility label maps before startup.

No database migration or reindex is required. Existing vectors remain valid
when the primary embedding provider/model is unchanged. Switching embedding
models still requires a new compatible index or a full reindex.

The relationship-query module is unchanged and explicitly outside this
release's semantic-correction claim.
