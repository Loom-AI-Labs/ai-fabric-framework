# AI Fabric 0.8.49

Status: MAIN approved immutable publication on 2026-11-11 after source review,
the pinned Java 21 native pass and the corrected core-provider scorecard.
Central availability and empty-cache public consumption are separate
post-publication gates. Based on immutable 0.8.48; no older artifact or tag is
replaced.

## Scope

- Let the authorized READ planner resolve INFORMATION requests before applying
  indexed-RAG restrictions. Retain the final retrieval-enabled, vector-space
  allowlist, routing and budget checks before actual indexed retrieval.
- Defer a missing vector-space decision only when the trusted execution
  context has a structurally qualified READ-planning path. Share eligibility
  with the READ planner: READ mode, enabled resolution, configured allowlist,
  effective capability restrictions, grounding eligibility, anonymous policy
  and a registered handler. This is not authorization to execute the action;
  the normal handler authorization, trusted bindings and native validation
  remain in the governed invocation path.
- Carry that context through compound, completion, repair, multi-step,
  progressive reassessment and legacy extraction. Context-free validation
  remains conservative. When no effective profile exists, an actions-disabled
  policy does not qualify for source-selection deferral.
- The pre-dispatch vector-space resolution step uses the same qualification
  before rejecting a still-missing source. Existing explicit model selections
  and trusted source/target hints retain their validation; the final RAG source
  selection remains mandatory if READ evidence cannot answer the request.
- Explain in managed extraction prompts that live READ tools are distinct
  from indexed retrieval. A READ tool does not require inventing a vector
  space or asking the user to choose an internal knowledge domain.

The original model retrieval decision is retained. No keyword routing,
automatic fan-out, forced ACTION intent, invented source or additional
recovery mechanism is added. A remaining request for indexed retrieval must
still pass all existing policy and source-selection checks.

## Compatibility

No new configuration or public endpoint is required. Existing READ/action
allowlists, authentication, trusted runtime fields, native schemas, write
confirmation and retry contracts remain unchanged. No database migration,
reindexing or vector copy is needed. All modules must use the 0.8.49 BOM.
