# AI Fabric `0.6.1`

- **Release date:** 2026-09-14
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.6.1`
- **Compatibility baseline:** `0.6.0`
- **Java:** 21
- **Spring Boot:** 4.1.x
- **Primary proofs:** `incident-investigation-room` and
  `agentic-ai-action-resolver`

AI Fabric `0.6.1` is the first hardening patch for bounded multi-specialist
chains. It corrects manifest specialist identity, strengthens structured
manager generation around capability-control requests, and adds a second
production-style chain proof in the Account Resolver domain.

The `0.6.0` tag and Maven artifacts remain immutable. These changes require
the new `0.6.1` source tag and Maven Central artifacts.

## What Changed

### Effective identity for manifest specialists

A compiled manifest specialist's `contentHash` now covers:

- the raw specialist manifest content hash;
- the exact resolved prompt profile;
- the exact resolved input schema; and
- the exact resolved output schema.

AI Fabric canonicalizes that effective definition and hashes it as one unit.
Changing only a referenced prompt or schema therefore changes specialist
identity and invalidates protected work created under the previous semantics.

In `0.6.0`, a manifest specialist reported only the top-level manifest content
hash. That could let a prompt-only or schema-only deployment change retain the
same specialist identity. The runtime still validated the new resource, but
durable definition-drift checks could not distinguish it from the old
executable behavior.

Java-defined specialist hashing is unchanged.

### Bounded manager structured-output hardening

The shared structured specialist finalizer now states that:

- schema-validated application input may describe the requested operation and
  supplied parameters;
- application input never grants identity, authority, capabilities, evidence
  access, or permission;
- server-owned specialist instructions control routing behavior;
- external or application-state claims still require supplied grounding;
- worker, tool, target, and capability names alone do not establish domain
  intent; and
- an unavailable or unapproved capability must not be silently replaced by a
  different approved operation.

For the exact five-field bounded-chain directive contract, a shape-correction
attempt also reminds the model of the structural invariants for `ASK_USER`,
`INVOKE_ONE`, `INVOKE_PARALLEL`, `HANDOFF`, and `COMPLETE`. The correction does
not echo rejected model content. Java schema, policy, catalog, budget,
grounding, and authorization checks remain authoritative.

This is not text-matching routing and does not add a fallback worker. A bad
provider decision remains visible after the bounded correction budget is
exhausted.

### Second-domain bounded-chain proof

`agentic-ai-action-resolver` now registers `account-smart-resolution@1` with:

- exact manager `account-resolution-chain-manager@1`;
- account-read worker `account-resolver-manager-read@1`;
- billing-policy worker `billing-resolution-manager-advisor@1`;
- application-owned typed input mapping and result projection;
- backend-owned identity, account, tenant, deployment, conversation, and
  scopes;
- protected JDBC checkpoints, status, cancellation, restart recovery, and
  exact replay; and
- a public UI that shows bounded projected facts and execution lineage without
  raw worker/provider payloads.

One natural-language endpoint proves account-only, billing-only, independent
parallel, explicit adaptive sequential, missing-input clarification,
capability-only completion, invented-target protection, and one terminal
read-only handoff. The app's existing direct specialists, typed input waits,
fixed plans, backend conversation, proactive event execution, governed write
receipts, and human-review desk remain available for comparison.

## Dependency And Configuration

Use the patch BOM:

```xml
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>io.github.loom-ai-labs</groupId>
      <artifactId>ai-fabric-bom</artifactId>
      <version>0.6.1</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
```

No new framework property is required. Applications enabling durable chains
still need a datasource and two stable, distinct secrets of at least 32
characters:

```yaml
ai:
  execution:
    specialist-chains:
      enabled: true
      durable-enabled: true
      allow-ephemeral: false
      initialize-schema: false
      encryption-secret: ${AI_SPECIALIST_CHAIN_ENCRYPTION_SECRET}
      fingerprint-secret: ${AI_SPECIALIST_CHAIN_FINGERPRINT_SECRET}
```

## Migration

Applications using only Java-defined specialists can upgrade from `0.6.0` and
run their existing regression suite.

Every manifest-defined specialist receives a new effective hash under `0.6.1`,
even when its referenced resources did not change, because `0.6.0` used a
different hash composition. Before replacing a running `0.6.0` deployment:

1. Inventory active durable chains, durable specialist jobs, confirmable action
   receipts, and human-review tasks linked to manifest specialists.
2. Prefer draining those operations under `0.6.0` before deployment.
3. If draining is impossible, accept the intended fail-closed
   definition-change result and deliberately recreate the operation under
   `0.6.1` after reauthorization.
4. Do not rewrite stored hashes or copy terminal state into a new definition.
5. Keep all state-protection secrets stable across the deployment.
6. Verify health-reported specialist and chain hashes, then test exact replay,
   changed-payload conflict, cross-owner denial, and one real-provider route.

Process-local input waits and fixed-plan checkpoints do not survive restart in
either release. Existing Java-defined specialist receipts/jobs keep their
normal identity semantics.

## Scope

This patch does not add recursive workers, dynamic target discovery,
WRITE-capable chain workers, partial-success fan-in, model-authored graphs, or
exactly-once provider invocation. Those remain outside the bounded `0.6.x`
contract.
