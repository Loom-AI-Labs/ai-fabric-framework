# AI Fabric 0.8.51

## Scope

This patch simplifies INFORMATION READ planning after the retained 0.8.50
sign-in and public-source selection misses. Authentication is owned by the
server, not a separate model decision. Protected READ selection still returns
the existing host authentication requirement before parameter resolution or
invocation. Signed-in READs retain trusted identity, ownership and execution
authorization checks. Writes, confirmation and vector permissions are unchanged.

The planner catalogue now distinguishes retrieval permission from an available
indexed route using cooperation policy and authorized source availability.
Default, optimized, support and commerce prompts use those available choices
and clarify that hidden trusted parameters are supplied and checked by the
server, not reconstructed from their deliberately public-only schemas.

There is no phrase-based routing, forced READ selection, source fanout,
answer replacement, new semantic-recovery policy or automatic retry loop.
Unknown model decisions do not become an authentication grant or tool call.
The model remains responsible for the relevant capability/source selection;
the patch does not claim perfect semantic accuracy.

## Verification

- Java 21 release-profile reactor: 2,415 tests, no failures, errors or skips.
  All separately gated integration suites compile. The final default-prompt
  bundle was rebuilt and its 14 tests passed after review clarified the honest
  missing-evidence exit.
- Real OpenAI GPT-5.4-mini native-schema suite: 10/10 scenarios passed, using
  14 orchestration turns and one direct planner call. Both original natural and
  explicit subscription-status questions challenge anonymous callers without
  invocation, then execute the trusted owned READ for signed-in callers. Public
  policy READs, nullable/collection parameters, confirmation, rejection and
  declared no-confirmation writes also passed. No failed model case was replayed.
- OpenAI/ONNX/Lucene core matrix: 11/11 considered tests passed. Its existing
  harness clamps the configured minimum of 20 to the 11 tests in this chunk;
  this is not a 20-case or all-provider qualification.
- Regression coverage retains unknown/unlisted/write-action denial, trusted
  identity binding and separation of model READ decisions from the server's
  authentication outcome. Planner catalogue tests cover disabled retrieval,
  empty authorized sources, disabled RAG cooperation and an available route.
- Vector contracts: 18 local-provider and eight Docker-backed provider cases
  passed, with no failures or skips. The standalone agentic consumer passed
  5/5 tests. All seven repository release guards passed.

The broad real-app CI previously had 14 unrelated Incident Room failures on
0.8.49 and 0.8.50. This patch does not repair that baseline or claim that the
entire release checklist, every provider and every deployed demo is green.
Consumer adoption and hosted qualification are recorded separately.

The catalogue guides model selection; it does not replace a wrong semantic
choice with an inferred READ or add a recovery policy. Existing RAG cooperation
and downstream authorization checks remain. Model variability and the separate
generation/intent paths are not eliminated by this change.

## Consumer Impact

Adopt the 0.8.51 BOM, rebuild and apply the compatible executable artifact.
Existing immutable releases do not update automatically. The typed host sign-in
contract is retained. No database migration, reindex or vector copying is needed.
Custom READ-planner prompt overlays should include the server-owned knowledge
catalogue and use its availableDecisions/ragAvailable fields; they must not ask
the model to choose REQUEST_AUTHENTICATION. Keep execution authorization enabled.
