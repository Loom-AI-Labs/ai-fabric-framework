# AI Fabric 0.8.57

## Scope

### Preserve Completed Repair Decisions

Semantic recovery preserves validated sibling choices without restoring an
explicitly rejected missing execution decision over the model's valid repair.
Only a null decision with its corresponding typed validation issue can receive
the repaired value. Source, action, parameter and other already validated choices
remain protected, and the final result still passes normal validation.

Diagnostics distinguish preserving validated fields from preserving an entirely
valid sibling and identify the repaired decision fields. This is not a new
repair round, inferred Boolean default or general-purpose intent merger.

### Distinguish Evidence From A Draft Answer

The READ planner no longer receives the extractor's tentative `directAnswer` as
evidence. Its existing prompts receive an explicit summary of completed READs,
grounding-usable READs, conversation messages and active target references.
Counts update within the existing planning loop. Catalogue descriptions identify
available capabilities; they are not returned business facts.

Shared guidance explains when a question needs available authorized READ evidence
and when supplied history supports an answer without a tool. No READ is forced,
no source is invented, and indexed knowledge is not required merely to use a
public READ capability.

Custom READ-planner user templates can include `{{evidence_inputs_json}}` to show
the new availability summary. Existing templates that do not use it still render;
the framework does not impose a new semantic validation gate on custom prompts.

When parallel cooperation requires indexed evidence after a READ, the catalogue
advertises the combined READ-plus-RAG decision rather than offering a misleading
READ-only choice. Context-only continuation stays available; optional-RAG and
no-index modes retain their READ-only choice. Legacy model decisions still use
the existing execution policy, and the framework does not invent a missing source.

### Answer The Current Question From Checked Facts

Forced READ post-action generation now receives the existing processed user
question in the same generation call. Previously it could receive facts and an
instruction to answer the request without the request itself. Non-forced write
narration and authoritative action receipts are unchanged.

Shared evidence guidance distinguishes current blockers, satisfied conditions and
unknown checks. A negative question is not evidence of a problem, and an earlier
problem may have been resolved. No output matching, canned answer replacement,
second generation call or critic loop is introduced.

Static answer policy now has a separate `rag/generation/system` template and is
sent in the system role. It is rendered without dynamic values: user questions,
retrieved facts and approved conversation messages are never promoted to that
role. The existing history-reference policy remains alongside it. The text-only
helper has a backwards-compatible system-instruction overload retaining its
existing purpose defaults, token cap and single provider request.

The Account Resolver moves its static decision rules into this system template;
its user template contains only the question and evidence. Custom static system
overlays must not require dynamic placeholders. Existing user-template overrides
remain supported; this patch does not promote their dynamic content or managed
preview fields into system authority.

## Account Resolver Example

The example distinguishes checking account eligibility from placing an order,
requires the current extraction contract's explicit execution decisions, and
aligns source guidance with server-owned catalogues and recovery policy. Its
completion overlay now has the same trusted current-account scope as the initial
extraction stages; missing-field repair must not turn the account into an
external attachment target. The existing completion call and budgets are reused.

Its answer overlay evaluates supplied required checks together, corrects unsupported
premises, and exposes missing evidence without claiming an unchecked condition
has failed or succeeded. Configured round budgets are unchanged.

Its profile READ declares that identity-verification status, fraud-check results
and order history are not reported by that source. This is data-coverage
metadata, not a failed verification, a fabricated business status or a new
readiness computation. Current profile facts, ownership and receipts are unchanged.

The example uses the existing per-purpose provider configuration to default
answer generation to the qualified `gpt-5.4-mini-2026-03-17` snapshot, independently of its routing model. Routing
still uses `OPENAI_MODEL` (default `gpt-4o-mini`); `GENERATION_MODEL` overrides only
the example's answer model. This is not a framework-wide or other-app default.
The former answer model still made contradictory claims with correct input
facts, so model qualification is part of the example's quality assessment.

## Adoption

Rebuild and deploy consumers to adopt the patch. No database migration,
reindexing, new framework setting or customer configuration rewrite is required.
All tenant, ownership, source, READ authorization, confirmation and execution
budget boundaries remain. Publication, Central-only consumption and hosted
adoption require separate evidence; source notes alone prove none of them.
