# AI Fabric `0.8.27`

- **Release date:** 2026-10-12
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.27`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.27` completes the bounded semantic-recovery contract for an
ACTION obligation that cannot be resolved to an exact registered action. The
configured LLM remains responsible for the replacement semantic decision;
framework code validates authority and completeness without deriving meaning
from query text.

## Structured Action Resolution

- The multi-step action-resolution stage now emits one closed structured
  decision per obligation: `ACTION`, `INFORMATION`, or `UNRESOLVED`.
- `ACTION` must identify an exact registered action from the supplied catalog.
- `INFORMATION` must include a complete model-authored information intent,
  retrieval/generation decisions, response profile, target-resolution
  decision, advanced-RAG decision, and either an exact registered knowledge
  source or explicit clarification data.
- `INFORMATION` is accepted only for the affected obligation when a prior typed
  validation issue and the server-owned semantic-recovery policy explicitly
  permit that transition.
- When no actions are visible, a policy-permitted recovery schema exposes only
  `INFORMATION` and `UNRESOLVED`; it cannot fabricate an executable action.
- A disallowed transition fails with `SEMANTIC_RECOVERY_NOT_ALLOWED`. An
  incomplete or unresolvable selection fails with
  `ACTION_SELECTION_UNRESOLVED`; neither path is presented as success.
- Valid sibling obligations retain their stable `obligationId`, intent type,
  and exact registered action.

## Read Actions And Evidence Domains

The default extraction guidance now follows the effective
`readActionResolutionEnabled` policy consistently. Factual and lookup requests
remain `INFORMATION` when the server is configured to plan eligible read
actions after extraction; explicit operations and direct operator commands can
remain `ACTION`.

Read actions are not inherently coupled to indexed vector spaces. An action
may fetch live or operational entities without declaring
`groundingVectorSpaces`. When that optional metadata is present, it is an
explicit evidence-domain constraint and exact mismatch validation still
applies. When it is absent, the framework does not infer a domain mismatch or
silently broaden retrieval authority.

## Philosophy And Safety

This correction adds no natural-language keyword matching, phrase rules,
token scoring, domain-specific routing, or deterministic action-to-RAG
conversion. Exact identifiers, provider schemas, registered catalogs, and
server-owned allow-policies are validated deterministically. Semantic
replacement remains model-authored, bounded, observable, and fail-closed.

## Migration

Upgrade all AI Fabric artifacts through the `0.8.27` BOM. No database migration
or vector reindex is required. Existing semantic-recovery policy names remain
unchanged.

Deployments that intentionally permit unknown-action replanning must configure
`unknownAction=LLM_REPLAN_TO_INFORMATION`. Deployments that permit a declared
action/evidence-domain mismatch replan must configure
`actionDomainMismatch=DENY_AND_LLM_REPLAN`. Other policies do not authorize an
ACTION-to-INFORMATION transition.
