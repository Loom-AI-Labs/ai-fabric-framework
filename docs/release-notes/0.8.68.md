# AI Fabric Framework 0.8.68

Status: release candidate. Maven Central publication and hosted product adoption
must be verified separately. Previous immutable release: 0.8.67.

## Governed Bounded Workflows

- Opt-in `BOUNDED_ITERATIVE` specialist workflow over registered READ and WRITE
  actions. The model selects a next action, observes its approved result and
  decides again. Ordinary chat and existing read-only profiles remain unchanged.
- A trusted host binding narrows published actions, writes, model calls,
  corrections and time limits. It cannot originate from user chat input.
- Every dispatch uses the normal governed action boundary, effective caller
  scope and actual action confirmation policy. No-confirmation writers can
  execute; confirmation-required writers pause on the ordinary proposal contract.
- Protected checkpoints reuse the existing durable execution record and lease.
  Stable operation IDs, immutable request/authority/definition fingerprints and
  host receipt reconciliation prevent blind replay of uncertain writes.
- Root model admission covers planning, repairs and finalization. Provider
  accounting remains a separate host-enforced financial boundary.
- Typed candidate validation may use the finite correction allowance. Essential
  missing input, unsupported work, authorization, cancellation, provider failure,
  funding and deadlines stop execution. Actual completed effects remain visible.
- Optional canonical message protection and a history-preserving `INTERRUPT_AI`
  control command support private authoring conversations without a second
  transcript owner. Hosts remain responsible for their actual retention rules.
- The relationship-query module now declares its existing RAG production
  dependency explicitly; no relationship reasoning behavior changes.

See [Bounded Read/Write Workflows](../guides/bounded-read-write-workflows.md) for
manifest and host contracts. There is no implicit production in-memory recovery,
arbitrary external exactly-once guarantee, new tool authority or automatic funding.

## Qualification

The default 38-module test reactor passed locally, including focused planning,
confirmation, checkpoint, replay and cancellation tests. A wider Failsafe run
requires absent local ONNX assets and has fixture-dependent failures; it is not
claimed as passed. The release-module build and hosted CI remain explicit gates.
LoomAI's configured assistant migration is separate product work, not proof
supplied by publishing these framework artifacts alone.
