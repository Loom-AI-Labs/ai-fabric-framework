# AI Fabric `0.8.4`

- **Release date:** 2026-09-22
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.4`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.4` adds an explicit dispatch boundary for MCP actions that require an
application-owned connector adapter before their final MCP tool call.

## Added

`execution.mcp.dispatchMode` now supports two strict values:

- `DIRECT_GATEWAY`: use the existing Spring AI MCP or configured MCP gateway path. This remains the
  default when `dispatchMode` is absent.
- `CONNECTOR`: send the governed action request through the configured application connector while
  preserving the MCP action configuration in `trace.actionConfig`.

Example:

```yaml
execution:
  adapterType: mcp-tool
  mcp:
    dispatchMode: CONNECTOR
    serverRef: commerce
    toolName: update_resource
```

This supports applications whose connector must resolve application-owned state, adapt a logical
delta to a provider contract, or apply another authorized transformation before the final MCP
gateway invocation.

## Security Boundary

- Dispatch mode is trusted action configuration and cannot be supplied by the model or caller.
- Parameter schemas, evidence-bound values, authorization, confirmation, provenance checks, and
  idempotency behavior still execute before connector dispatch.
- The connector receives the standard action request plus the immutable action configuration and
  must return the standard `ActionResult` contract.
- Unknown dispatch values fail closed with `INVALID_CONFIGURATION`.
- There is no automatic fallback from connector dispatch to direct MCP execution.
- The framework contains no product, commerce-provider, or LoomAI-specific routing rules.

## Migration

No change is required for ordinary MCP actions. Add `dispatchMode: CONNECTOR` only to actions whose
application connector owns a required pre-MCP adaptation. Keep `DIRECT_GATEWAY`, or omit the field,
when the declared `argumentTemplate` can directly produce the provider payload.

AI Fabric `0.8.4` is the only current contract and replaces earlier framework/runtime contracts.
Consumers must upgrade their BOM and all AI Fabric artifacts together; there is no compatibility
mode or parallel old/new runtime requirement.

## Verification

- Connector tests prove connector-dispatched MCP actions use connector URL and credentials, retain
  `trace.actionConfig`, and do not invoke the local Spring AI MCP executor.
- Negative tests prove unsupported dispatch modes fail closed before any outbound call.
- Release completion requires the full framework reactor, release guards, release-profile artifact
  build, empty-cache Maven Central consumption, and a live consumer action canary.
