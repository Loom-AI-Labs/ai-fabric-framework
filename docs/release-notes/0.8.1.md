# AI Fabric `0.8.1`

- **Release date:** 2026-09-21
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.1`
- **Upgrade baseline:** `0.8.0`
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.1` is a focused security-preserving patch for governed actions that require explicit
confirmation and hidden parameters resolved from trusted application context.

## Fixed

Pending actions now persist the names of parameters that AI Fabric resolved from trusted context on
the proposal turn. A positive confirmation restores only those recorded trust markers while
replaying the stored action.

Previously, the pending action retained the resolved value but not its provenance. On the
confirmation turn, a valid hidden parameter such as a session-owned resource handle could therefore
be treated as client-supplied and fail closed with a trusted-application-context clarification.

The trust marker is carried through chat-session serialization and configured or annotated
confirmation interceptors.

## Security Boundary

- Only parameters returned by AI Fabric's context-resolution boundary are marked trusted.
- Positive confirmation does not trust every stored or hidden parameter.
- User-visible, evidence-bound, and executable-target checks retain their existing behavior.
- A hidden value placed into pending state without a matching trusted-resolution marker remains
  blocked.
- Pending records written by an older release have no trust marker and therefore continue to fail
  closed. The application can ask the user to repeat the original action request.

## Compatibility

- No database migration or configuration change is required.
- Existing four- and five-argument `PendingAction` constructors remain available.
- The persisted pending-action map gains an optional `trustedResolvedParameters` field.
- Existing chat, retrieval, indexing, document-ingestion, specialist, chain, review, and action
  contracts are otherwise unchanged from `0.8.0`.

LoomAI can upgrade directly from `0.7.1` to `0.8.1`. The `0.8.0` document-indexing migration rules
still apply; the dependency upgrade and document-workflow adoption remain separate gates.
