# AI Fabric 0.8.55

## Scope

Ordinary chat now includes registered knowledge namespaces when resolving its
mode-derived capability profile. An absent optional retrieval allowlist no longer
produces an empty effective source catalogue for the READ planner.

The source list remains constrained by configured allowlists and retrieval policy.
A required but missing allowlist, disabled retrieval, absent registration and an
explicit empty execution/task profile do not become unrestricted access. Explicit
task profiles are not rebuilt from ordinary-chat defaults. Model source selection,
search authorization, scope isolation, budgets and write confirmation are unchanged.

The existing action-only profile overload remains available to callers that do not
have a source registry. Ordinary chat supplies its server-owned entity registry;
no caller or model supplies that registry and no source name is hardcoded.

This corrects catalogue construction, not the semantic decision itself. It adds
no search-all recovery, automatic action execution, message matcher, canned answer
replacement or additional inference call. The narrow history-only continuation
contract introduced in 0.8.54 remains in effect.

## Adoption

Rebuild and deploy consumers. No new property, configuration rewrite, database
migration or reindex is required. Existing optional allowlists may remain absent;
do not add a deployment-specific source workaround to hide the catalogue defect.

## Verification

A Spring-wired regression reproduced the empty ordinary-chat profile before the
fix. Focused checks cover registered source discovery, configured narrowing,
missing required allowlists, disabled retrieval, missing/empty registries and
explicit task-profile ceilings. The real-provider gate uses real embeddings and
indexed guide retrieval with no optional source allowlist, alongside private READ
authentication, declared confirmation and informational follow-ups.

Public-package and hosted-consumer verification are separate release gates;
source pins and this note are not deployment receipts.

The 30-module release-profile reactor and all 1,139 core tests passed. Release
guards, external local consumers and integration-suite compilation passed. The
Docker-backed vector contracts passed, including eight container integration
cases. Real OpenAI qualification passed 21 scenarios / 26 entry calls; the
OpenAI/ONNX/Lucene core matrix passed separately.

The indexed fixture declares its one actual guide namespace, no optional source
allowlist and an explicit 0.5 relevance cutoff. Its real embedding calibration was
0.598 for a representative generated query. This is test configuration, not a
framework-default change. Earlier candidates remain recorded: a shared fixture
exposed unrelated unseeded namespaces, and an uncalibrated 0.7 cutoff excluded a
relevant guide even after correct source selection. This patch does not claim
universal multi-source relevance or perfect model choices.
