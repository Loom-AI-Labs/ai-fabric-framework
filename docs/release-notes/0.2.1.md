# AI Fabric 0.2.1

**Released:** 2026-06-16 · **Coordinates:** `io.github.loom-ai-labs` · **Latest stable:** `0.2.1`

`0.2.1` is the recommended release on the new, unified **AI Fabric** naming. It folds in the `0.2.0`
naming normalization and fixes a component-scan regression from that rename, so multi-module
applications wire up correctly. It also ships an offline **smoke profile** that lets every bundled
example application boot with no API keys and no external services.

> Using `0.1.0` or `0.2.0`? Upgrade to `0.2.1`. `0.2.0` contains a component-scan bug (see below) and
> `0.1.0` uses the old coordinates/packages. Migration notes are at the end.

---

## Highlights

- **One consistent identity.** Every artifact is `ai-fabric-*` and every package is `ai.fabric.*`,
  imported through a single BOM.
- **Reliable auto-configuration for multi-module apps.** Fixes a regression where the core
  component-scan re-scanned feature packages it should have excluded, breaking bean wiring in apps
  that combine modules (e.g. relationship-query).
- **Run the examples with zero setup.** A new `smoke` profile boots all 11 real-app examples offline —
  great for evaluating the framework, demos, and CI.

## Add it to your build

```xml
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>io.github.loom-ai-labs</groupId>
      <artifactId>ai-fabric-bom</artifactId>
      <version>0.2.1</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
```

```xml
<!-- Spring Boot starter: pulls in the core auto-configuration -->
<dependency>
  <groupId>io.github.loom-ai-labs</groupId>
  <artifactId>ai-fabric-starter</artifactId>
</dependency>
```

Pick the provider and vector-store modules you need (versions are managed by the BOM), e.g.
`ai-fabric-provider-openai`, `ai-fabric-onnx-starter`, `ai-fabric-vector-lucene`,
`ai-fabric-vector-qdrant`, `ai-fabric-relationship-query`, `ai-fabric-rag`, `ai-fabric-pii`.

## What's fixed

### Component-scan excludes (the reason for this patch)
`AIInfrastructureAutoConfiguration`'s `@ComponentScan` exclude filters still used the pre-rename
regex (`com\.ai\.infrastructure\.*`). After the `0.2.0` package rename those patterns matched
nothing, so core re-scanned `ai.fabric.behavior/chat/rag/relationship/web/migration/it/config` —
packages that are meant to be configured by their own module auto-configurations. The double
registration broke the conditional bean wiring in multi-module apps (for example, the
relationship-query module's `ReliableRelationshipQueryService` was no longer created, so an app
combining it with the web layer failed to start). `0.2.1` repoints the patterns at `ai.fabric.*` to
restore the intended exclusions. The full framework test suite passes with the fix.

## What's new

### Offline `smoke` profile for the examples
The `examples/real-apps` suite gains a shared `smoke-support` module and a Spring `smoke` profile so
each example boots **without any API keys or external services**:

- a deterministic local `AIProvider` and a deterministic, in-process `EmbeddingProvider` (no ONNX model file needed),
- an in-memory vector store and an in-memory H2 database,
- config that points the framework's `llm-provider` / `embedding-provider` / `vector-db.type`
  selectors at those local backends.

Run any example offline:

```bash
mvn -pl <app> spring-boot:run -Dspring-boot.run.profiles=smoke
# or
java -jar <app>/target/<app>.jar --spring.profiles.active=smoke
```

All 11 examples are verified to start under this profile, and CI now boot-tests them on every change.

## Carried over from 0.2.0 (naming normalization)

- Artifacts: `ai-infrastructure-*` → `ai-fabric-*`, `ai-curated-*` → `ai-fabric-curated-*`.
- Java packages: `com.ai.infrastructure.*` → `ai.fabric.*`, `com.ai.curated.*` → `ai.fabric.curated.*`.
- Spring auto-configuration, `spring.factories`/`AutoConfiguration.imports`, and configuration
  metadata updated accordingly. Public entry-point class names (e.g. `EnableAIInfrastructure`) are
  unchanged.

## Upgrading

### From 0.2.0
Bump the version to `0.2.1`. No source changes are required — this is a drop-in fix.

### From 0.1.0
1. Change the groupId/coordinates to `io.github.loom-ai-labs` and the BOM to `ai-fabric-bom:0.2.1`.
2. Rename dependency artifactIds: `ai-infrastructure-*` → `ai-fabric-*`, `ai-curated-*` →
   `ai-fabric-curated-*`.
3. Update imports: `com.ai.infrastructure.*` → `ai.fabric.*`, `com.ai.curated.*` →
   `ai.fabric.curated.*`.
4. Spring **configuration property** prefixes are unchanged (e.g. `ai.providers.*`,
   `ai.vector-db.*`) — only Java packages and Maven coordinates moved.

`0.1.0` and `0.2.0` remain available on Maven Central but are not recommended.
