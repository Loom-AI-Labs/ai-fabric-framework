# AI Fabric 0.8.53

## Scope

Conversation intent extraction now receives the server-observed presence or
absence of a pending action as trusted system context, separately from user text,
retrieved documents and pinned targets. Recent conversation messages are retained.
Accepting an offer to explain, summarize or produce a checklist is not approval
of an executable operation. Pending parameter values and private descriptions
are not inserted into this control prompt.

Conversation reference guidance also preserves the output offered by the
assistant, including its format, without treating historical statements as
current evidence or permission for a write.

The necessary execution contract is that confirmation must identify a real
pending operation. A model-selected confirmation when the server observed none
produces the typed issue `CONFIRMATION_WITHOUT_PENDING_ACTION`; the server does
not silently change it to INFORMATION or manufacture a pending action.

## Configuration

`ai.orchestration.semantic-recovery.confirmation-without-pending` defaults to
`FAIL`. A global or existing mode-level override can explicitly select
`LLM_REPLAN_THEN_FAIL` to feed the typed finding and original conversation back
through the existing progressive extraction flow. Its configured model-call cap,
strategy switches and provider budgets still apply. Attempts and actual model
transitions remain visible in extraction diagnostics. Failure stays visible if
the correction is disabled, unavailable, or unsuccessful.

```yaml
ai:
  orchestration:
    modes:
      executor:
        semantic-recovery:
          confirmation-without-pending: LLM_REPLAN_THEN_FAIL
```

The model decides the replacement intent. Registered actions still pass their
normal authorization, parameter and confirmation contracts. A valid sibling
obligation cannot be dropped by a correction, including a candidate deferred to
an explicitly configured vector-space policy. An unfinished action draft still
continues normally when the pending-confirmation store is empty.

No query-word matcher, canned replacement answer, automatic search-all or new
side-effect permission is introduced. No database migration or reindex is needed.
Consumers must rebuild and deploy the new runtime artifact; published snapshots
do not update automatically.

pending/empty/unavailable state, owner isolation, draft continuation, policy
opt-in/disable, correction limits, generation history and compound-obligation
preservation. Release guards, separately gated integration-suite compilation,

and informed prompt/test improvements, not hidden by successful HTTP status.
