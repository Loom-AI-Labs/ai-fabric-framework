# AI Fabric 0.8.38

## Canonical Anonymous Authentication

This patch fixes authentication checks for anonymous sessions using the canonical
conversation request envelope. Previously, the presence of a trusted execution
context made a request authenticated, bypassing registered `anonymousAllowed=false`
action gates even when the host had verified only anonymous-session ownership.

`ExecutionPrincipalType.ANONYMOUS_SESSION` now represents that verified anonymous
owner and is valid only for `ExecutionSource.INTERACTIVE`. Trusted ownership no
longer implies authentication. Protected actions are denied before handler
validation or execution; explicitly guest-safe actions remain available.

Anonymous access-control projection uses the initiator ID as subject and session,
`ANONYMOUS_SESSION` as subject and caller type, `TRUSTED_INTERACTIVE` as auth mode,
and only trusted tenant, deployment and granted scopes. Request metadata cannot
upgrade that identity. End-user, service and system authentication is unchanged.

## Adoption

Upgrade the BOM to `0.8.38`. Consumers must explicitly map verified anonymous
sessions to `ExecutionPrincipalType.ANONYMOUS_SESSION`, not `END_USER`. Do not remove
the trusted envelope or route canonical requests through a legacy overload.

Consumers that permit anonymous entity access must explicitly authorize the new
server-owned anonymous contract under their existing anonymous opt-in, exact
tenant/deployment scope and query-scope checks. The framework does not grant that
access automatically or fabricate JWT issuer, audience or expiry claims.

There are no database/schema migrations, reindexing requirements, prompt changes,
model changes or provider configuration changes. Existing conversation ownership,
approved snapshots, control epochs, turn guards and persistence policy are retained.

## Verification

Focused local qualification covers the reproduced protected-action regression,
anonymous auth projection and metadata, signed-in/service/system controls,
conversation scope and fencing, and deterministic chat/conversation-control tests.
All 240 focused checks passed with zero failures, errors or skips: 117 core/auth,
93 chat-session and 30 execution conversation checks. Repository release guards
also passed. Real-provider and vector matrices are outside this identity-only
change. Local qualification is not publication, runtime adoption or hosted
customer-journey acceptance.
