# AI Fabric Framework 0.8.67

Status: local release candidate; publication and hosted adoption are not yet
verified. Previous immutable release: 0.8.66. New behavior is opt-in.

## Retrieval And Optional Reranking

- Typed dense/hybrid/keyword retrieval profiles, finite candidate and evidence
  bounds, per-source lexical readiness and visible degradation policy.
- Weaviate native BM25F plus independent dense retrieval, with one framework-owned
  reciprocal-rank fusion across selected document/entity spaces. Same source,
  type, document version and chunk identity are retained through ranking.
- Multi-space chat uses the shared-profile request once rather than applying a
  second merger or comparing RRF scores with cosine thresholds. Failed profiled
  retrieval stops generation; it is not converted into a successful empty search.
- Optional provider-neutral reranker SPI and Cohere adapter. Ranking is OFF by
  default. Only bounded, host-authorized excerpts leave the host; returned
  references can reorder originals, not inject new evidence or provider text.
- Native calls require a host-supplied accounting admission bridge. There is no
  automatic allowance, alternate key, redirect or retry. Actual billing units
  are supplied to the bridge; unverified outcomes retain their reservation.
- Explicit availability-only pre-rerank fallback may retain the authorized
  search order with diagnostics. Authentication, funding, malformed receipts and
  foreign/duplicate references do not become availability fallback.
- Advanced RAG delegates request-, configuration- and provider-default profiles
  synchronously to this one path, retaining the bounded context, selected order
  and diagnostics. No legacy expansion, second ranking or context-model call
  is added. The earlier behavior remains separate on unprofiled requests.
- Conflicting content under one versioned evidence identity fails visibly in
  either a fused or single-leg result, including duplicates within one leg.
- Context formatting preserves attribution and reports bounded truncation.
- Late native retrieval results are rejected after the shared deadline. Native
  adapters still own transport timeouts; synchronous SDK calls are not forcibly
  preempted by this check.
- Keyword-only retrieval skips embedding and dense-provider calls, with explicit
  unused-embedding metadata rather than an invented provider/model receipt.
- A request can opt out of configured reranking for a controlled baseline. It
  cannot enable a host-disabled provider, grant consent/funding or mutate the
  saved profile. Normal requests still use the configured ranking stage.

## Example Qualification Correction

Incident Room's access policy assumed that an interactive caller's ID was the
incident ID. That assumption also fails against 0.8.66, which preserves caller
identity separately from the object being inspected. The example now resolves
an interactive caller through its active owned session and still verifies the
tenant, incident deployment, specialist scope and exact action scope. Backend
service calls retain their explicit incident boundary. Its registered chain
manager is included in the example's exact specialist allowlist. No framework
identity rewrite, wildcard permission or access-check bypass is introduced.

The next hosted run exposed a pre-existing JSON Schema validator 3.0.0 crash on
nullable numeric fields with bounds. The dependency is patched to 3.0.4, which
includes the upstream type-array correction. Regression tests cover all four
numeric bounds, null handling, strict types and invalid values. No schema,
required-input or action-validation rule is relaxed to make startup pass.

## Compatibility And Boundaries

Existing profiles and search paths remain unchanged without an explicit typed
profile. Unsupported stores report dense-only readiness; this candidate does
not add Milvus native full-text indexing or claim hybrid support for every
provider. Source authorization, tenant/audience filters and active-version
filtering remain host responsibilities and precede external reranking.

Ragas worker integration, customer UI, financial grants, document indexing
operations and hosted product rollouts belong to the separate LoomAI product
work. They are not implemented by this public framework release alone.

## Qualification

Candidate-source regression: 1,366 executed tests passed, zero failures/errors;
one explicitly opt-in Weaviate live test skipped in the ordinary unit run.
Separate native read-only Weaviate probes passed on two existing corpora.
Two native Cohere v5 Fast/Pro calls verified references and input-token receipts
using public/synthetic excerpts, not private customer records. These are adapter
checks, not evidence of a general natural-question quality improvement.

Complete release-profile, container/consumer verification, publication and
hosted adoption remain required before changing this candidate status. Do not
claim production adoption or promote defaults from unit/native-adapter checks.

The first hosted candidate run passed framework/vector contracts but failed
Incident Room integration on that policy mismatch; it was not treated as a
passing release. The corrected example's 34 focused integration/access tests
passed locally. The final hosted verification rerun remains required.
