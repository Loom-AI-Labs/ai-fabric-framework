# AI Fabric 0.8.47

Based on immutable 0.8.46. Do not move or reuse a published tag. Local
qualification is separate from Central publication and live adoption.

## Scope

- Add the explicit specialist write policy `ACTION_POLICY`. Authorized WRITE
  actions whose existing confirmation policy does not require confirmation
  use the existing governed invocation path. Confirmation-required actions
  still produce the existing durable proposal; they are never auto-confirmed.
- Bind the server-owned `specialistActionPolicyWrites` flag from the registered
  definition, overwriting adapter values. The flag defaults to false and is not
  accepted from request JSON. Existing capability, schema, authorization and
  execution limits remain enforced. `CONFIRMATION_RECEIPT_REQUIRED`, default
  specialists and general/chat behavior retain their existing contracts.
- Add default `OrchestrationTurnGuard.afterAction(metadata, context, outcome)`.
  It observes each actually dispatched handler outcome once, including failed,
  unknown and null-result outcomes. Pre-dispatch denials do not call it.
  Hook exceptions are logged without replaying or changing the handler outcome.
- Add `ActionProposalCoordinator.decide(request, trustedContext, guard)` for
  host-governed confirmation outside orchestration. Attach the guard to the
  freshly resolved action context before preflight and preserve it across both
  confirmation CAS retries. Active decisions and final dispatch enforce the
  guard; completed receipt replay does not become a false deadline failure.
  The two-argument API delegates with null, leaving human-review callers unchanged.
- Proposal creation and decision revalidation use a non-executing
  `PROPOSAL_PREFLIGHT` state. A changed confirmation policy cannot dispatch
  an action during validation or before a durable decision is recorded.

There is no second executor, semantic matcher or fallback. No DB schema, state
protocol, recovery, draining, indexing, provider or chat endpoint change is
included. `AIExecutionResult` is unchanged. Runtime, Platform and UI integration
are consumer-owned work, not supplied or certified by this framework candidate.

## Consumer Notes

Keep all framework modules aligned through the 0.8.47 BOM. Specialists must
explicitly register `ACTION_POLICY` and their existing bounded write allowlist.
The policy grants no authority beyond the current effective capability profile.

Hosts needing Task-side receipts may override `afterAction`. It is an observer,
not an authorization hook. Keep trust enforcement in the existing pre-execution
guard. For out-of-pipeline confirmation, call the new three-argument `decide`
overload with the current host guard; do not attach guards to stored receipts.
The hook runs before later synthesis or result processing and does not expand
the public execution result contract.
