# AI Fabric 0.8.56

## Scope

Iterative READ planning retains its latest model-selected retrieval source and
associated query when a later planning step omits them but the effective policy
still requires RAG. The selection belongs only to the current resolution call.
A later explicit selection replaces it; source sets are not merged and no
namespace is invented from the catalogue or user message.

The retained selection passes through the same registered-source, allowlist,
capability, tenant and retrieval-budget boundaries. Invalid later selections are
not replaced by an earlier valid one. No additional model call, action replay,
hidden search-all recovery or natural-language matcher is introduced.

Diagnostics identify carried-forward plans, their originating iteration and the
model-selected query. The final planning decision and every iteration remain
visible. Optional retrieval is not enabled merely because an earlier step named
a source, and existing context-only continuation rules remain unchanged.

## Account Resolver Example

The example explicitly enables its existing bounded missing-source recovery
within the same two-source allowlist and max-spaces budget. Its container now
pins 0.8.56. Packaged application/build metadata takes precedence over stale
runtime labels, so a retained environment variable cannot conceal the new image
identity when build metadata is present.

This corrects routing and diagnostics, not all model wording. A successful
account update, its confirmation and actual receipt remain authoritative;
semantic answer quality must be reviewed separately from routing success.

## Adoption And Verification

Consumers must rebuild and deploy the new artifact. No database migration,
reindex, customer configuration rewrite or new framework property is required.
The explicit bounded-recovery setting is example configuration, not a new
framework-wide default. Existing authorization and source ceilings remain.

A regression reproduces loss of the selected source before the fix. Focused
checks cover source/query retention, explicit replacement, invalid replacement,
request isolation, missing selections, optional RAG and the existing downstream
source/fan-out boundaries. Public publication and hosted adoption are separate
verification gates; these source notes are not deployment receipts.

This is a scoped routing release, not an all-scenarios quality pass. The example
can still produce contradictory eligibility wording despite correct profile
facts and successful routing. Those semantic findings remain separate work;
they are not repaired by canned wording, replaying a write or relaxing authority.
