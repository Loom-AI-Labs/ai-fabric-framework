# AI Fabric `0.8.11`

- **Release date:** 2026-10-05
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.11`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.11` makes configured context resolvers authoritative for hidden
action parameters. A type-valid value proposed by an LLM can no longer bypass
resolution from trusted attachment, runtime, owned-resource, or read-action
context.

## Fixed

- Hidden parameters with `resolveFrom` are always resolved from their configured
  trusted source before action validation or execution.
- A trusted resolved value replaces any model-proposed value for the same hidden
  parameter.
- If the trusted source cannot resolve the value, the untrusted model value is
  removed and normal fail-closed validation applies.
- Trusted hidden parameters restored for a confirmation continuation remain
  valid when the original request attachment is no longer present.
- Public, user-supplied parameters retain their existing schema validation and
  clarification behavior.

The implementation is action- and domain-neutral. It does not inspect action
names, parameter names, attachment text, or application-specific identifiers.

## Migration

Consumers must upgrade the BOM and all AI Fabric artifacts together to
`0.8.11`. No compatibility mode or parallel old/new runtime is required.

Action definitions that depend on a trusted internal target should declare the
parameter as `INTERNAL`, `SYSTEM`, or `SECRET` (or set `askUser: false`) and
provide an explicit `resolveFrom` contract. Candidate metadata keys remain an
application-owned configuration concern.

## Verification

- focused context-schema and context-resolution tests
- model-value replacement from trusted attachment metadata
- fail-closed removal when trusted resolution is unavailable
- confirmation-continuation retention for previously trusted parameters
- full `ai-fabric-core` test suite (`700` tests)
- framework release guards and CI reactor verification
