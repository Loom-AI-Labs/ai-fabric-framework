# AI Fabric 0.8.37

## Conversation Transaction Ownership

This patch fixes JDBC conversation-control writes participating in a host-owned
transaction, including applications using Spring JPA.

The JDBC store previously constructed an independent transaction manager. When
combined with an application-owned transaction on the same data source, a control
transition could commit before the surrounding handover, outbox or application
work committed. A later application rollback could leave the conversation in the
new control state without the corresponding handover record.

The Spring configuration now uses the application's available transaction manager.
The store also accepts an explicitly supplied `PlatformTransactionManager`.
Applications without a transaction-manager bean retain the standalone JDBC setup.
Ambiguous transaction-manager beans are not silently selected; declare a primary
manager or provide the conversation store explicitly.

## Adoption

Upgrade the BOM to `0.8.37`. There is no database migration, reindexing, prompt,
model, provider, authorization or conversation-state-machine change.

Spring Boot applications with one data source and the normal JPA transaction
manager use the shared manager automatically. Application-owned JDBC repositories
that write alongside conversation control must use that same manager.

For explicit store construction:

```java
var store = new JdbcConversationControlStore(
    dataSource,
    objectMapper,
    false,
    applicationTransactionManager
);
```

The supplied manager must manage the supplied data source. Use reviewed application
migrations rather than runtime schema initialization in production.

## Verification

- All 93 chat-session module tests passed, including new real Spring JPA/H2
  commit-visibility and rollback regressions.
- An external runtime consumer passed 22 focused checks, including four actual
  PostgreSQL/JPA cases: direct handover, shared outer commit, outer rollback and
  dispatch failure. The prior release's failing rollback reports were retained.
- Existing conversation ownership, command replay, turn-lease and message-ordering
  checks remain enabled.
- Repository release guards and immutable artifact publication are separate gates;
  a successful local candidate test is not a hosted deployment acceptance claim.

Real-provider and vector matrices are not relevant to this transaction-only
change. Hosted applications must still adopt the published artifacts and verify
their own handover and application/outbox transaction boundaries.
