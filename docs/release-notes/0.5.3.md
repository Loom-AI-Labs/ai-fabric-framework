# AI Fabric `0.5.3`

- **Release date:** 2026-08-04
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.5.3`
- **Compatibility baseline:** `0.5.2`

AI Fabric `0.5.3` hardens the retrieval, MCP, Lucene, trusted-context, and
specialist-grounding paths exercised by the `0.5.x` agentic runtime and its
real-application verification suite.

## Trusted Retrieval Boundaries

RAG search now preserves filters even when response context and metadata are
not requested. When a trusted `AIAccessSubjectContext` is present, its tenant
and deployment identifiers become the canonical retrieval filters and replace
conflicting caller-provided values.

Together with the trusted execution-context correction in `0.5.2`, this keeps
verified identity boundaries intact from specialist invocation through the
optimized vector-search request.

## Lucene Reader Safety

The Lucene vector provider now leases searchers while reads are in progress.
Reader refresh and shutdown can no longer close the reader that an active
search, scan, count, lookup, or diagnostic operation is using.

The change removes transient missing-document results and
`AlreadyClosedException` retries under concurrent indexing and retrieval. No
application configuration change is required.

## MCP Execution Hardening

Spring AI MCP actions now:

- bind an exact configured `serverRef` to the MCP server-reported name or
  title;
- fail closed instead of selecting a different server that exposes a tool with
  the same name;
- initialize clients before inspecting server information or tools;
- reject invalid MCP response-limit configuration as a typed failure; and
- reject oversized tool results before they enter action projection or model
  context.

The optional response limit is configured per MCP action:

```yaml
execution:
  adapterType: mcp-tool
  mcp:
    serverRef: operations-reference
    toolName: inspect_service
    responseMapping:
      maxCharacters: 32768
```

The default is `32768` characters. Supported values are `1024` through
`262144`. Oversized results return `MCP_RESULT_TOO_LARGE`.

## Trusted Parameters And Read Grounding

Nested read actions now validate required parameters after backend-owned
context parameters have been resolved. Applications no longer receive a false
missing-parameter response for values that the trusted application context
already supplied.

Successful grounding-eligible read actions also expose a bounded canonical
grounding observation. Specialist manifests can require evidence from any
requestable read action with:

```yaml
grounding:
  sources:
    - type: ANY_REQUESTABLE_READ_ACTION
      minimumCount: 1
      groundingUsable: true
```

The compiler rejects this source when the specialist has no requestable read
actions, when a source name is supplied, or when vector-only evidence IDs are
configured.

## Real-Application Verification

The source release adds and hardens real applications that verify:

- agentic account resolution with typed waits, confirmation, durable receipts,
  and human review;
- tenant- and deployment-scoped specialist retrieval;
- sequential and parallel incident plans, bounded delegation, handoff, and
  conversation management;
- authenticated remote MCP reads and confirmed writes with exact server
  binding and replay-safe receipts;
- durable behavior analysis using prior insight plus fresh events; and
- authoritative live-indexing work states, retry, dead-letter, update, delete,
  restart, and concurrent Lucene retrieval behavior.

These applications are release evidence and deployment candidates. Maven
Central publishes the framework modules; deploying the applications remains a
separate operation.

## Upgrade Guidance

Most `0.5.2` applications can upgrade by changing only the BOM version.

Review these cases before deployment:

1. **MCP `serverRef`:** it must match the remote server's reported name or
   title, not a local client label.
2. **MCP result size:** configure `responseMapping.maxCharacters` when the
   default limit is unsuitable. Do not use a larger limit to pass unbounded
   provider output into model context.
3. **Trusted RAG filters:** tenant and deployment values from authenticated
   context now override conflicting request filters. Applications must not rely
   on caller values to weaken those boundaries.
4. **Specialist grounding:** `ANY_REQUESTABLE_READ_ACTION` is optional. Existing
   `READ_ACTION`, `VECTOR_SPACE`, and `ANY_ALLOWED_VECTOR_SPACE` manifests
   remain valid.

No intermediate deployment is required when upgrading from `0.5.0`, `0.5.1`,
or `0.5.2`, but adopters must also apply the security guidance from the
[`0.5.2` release notes](0.5.2.md).
