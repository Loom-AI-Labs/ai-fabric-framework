# AI Fabric 0.8.45

## Scope

Bounded action-draft lifecycle correction. No database migration, vector
reindexing, new provider, or change to action authorization is required.

## Changes

- Supplied public action values are no longer hard-rejected by keyword,
  description/name echo, or whole-query heuristics. An email containing
  `example.com`, for example, remains a supplied value. Blank/missing fields,
  declared types and schemas, hidden/system parameters, evidence-bound IDs,
  configured provenance policy and final confirmation remain enforced.
- The structured draft-continuation decision now includes `cancelsDraft`.
  Intentional abandonment of the current incomplete draft clears only its
  existing owner/conversation scope and returns an acknowledgement without
  executing a business action. Removal compares the exact observed draft;
  a concurrent replacement or completion is reported, not cleared or acknowledged.
  A conflicting continue/cancel decision or
  mismatched action cannot mutate the draft. A failed store mutation is not
  acknowledged as success.
- Default curated guidance distinguishes abandonment of an incomplete draft
  from cancellation of an already submitted business request. Questions about
  cancellation and unclear messages remain LLM decisions, not keyword routes.
- Chat-session history records the successful draft-cancellation acknowledgement
  even though it completes the orchestration pipeline early.

## Consumer Notes

No new application endpoint or form field is required. Existing public-only
`ActionDraftSubmission` forms still use the declared executable schema; internal
IDs must come from trusted application context. A submitted booking, payment or
other business record still needs its own separately authorized cancellation
action. Draft cancellation does not implement that business operation.

Custom curated overrides for `intent-extraction/action-draft-continuation`
should include the explicit cancellation decision and distinguish it from
continuation. Omitted cancellation is not inferred from user text. The LLM can
still make semantic mistakes; this patch does not claim perfect classification
or automatically replace a model decision.

Custom `ActionDraftStore` implementations must implement the conditional
`popDraft(..., ActionDraft expected)` operation atomically to support cancellation.
The built-in memory, legacy chat-session and canonical conversation stores do so.
There is no unsafe read-then-clear fallback for custom stores.

Serialize user turns within one conversation. This patch conditionally removes
the observed draft, but does not make the entire continuation-to-confirmation
lifecycle linearizable across simultaneous turns. An already in-flight
continuation can still recreate a draft after another turn cancelled it.
Existing final confirmation and authorization remain required; applications
must not advertise concurrent draft cancellation as a completed transaction.

## Verification

Pre-publication verification on Java 21 / Spring Boot 4.1.0:

- 1,026 tests passed with no failures, errors or skips: core 916, chat-session
  96 and default curated prompts 14. Release source/Javadoc packaging passed.
- Six real OpenAI `gpt-5.4-mini-2026-03-17` integration cases passed: three
  cancellation phrasings, policy/negation controls, and an example-domain value
  through confirmation and execution. The focused companion suite passed
  84 deterministic tests, including conditional removal and scope isolation.
- Framework release guards and whitespace checks passed.

Earlier failed attempts were retained and investigated; the full execution
canary exposed the duplicate keyword rejection in the argument binder before
publication. Unrelated provider/vector matrices were not manually rerun for
this bounded patch. Publication workflow, Central-only consumption and hosted
application evidence are separate gates; source tests do not prove those.
