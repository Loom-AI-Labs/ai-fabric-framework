# AI Fabric `0.8.12`

- **Release date:** 2026-10-09
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.12`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.12` corrects compound read retrieval so independent information
obligations and grounding-eligible read actions are collected once and combined
in one final grounded answer. It also makes retrieval routing provenance and
vector-space metadata explicit and fail-closed.

## Fixed

- Read-only compound requests collect each information intent's own optimized
  query, validated vector space, retrieved documents, and read-action evidence
  before performing one outward generation.
- Successful evidence is no longer hidden by selecting a single primary child;
  top-level documents, sources, read actions, child audit results, and bounded
  per-obligation diagnostics are retained.
- Grounding-eligible read actions execute once, child answer generation is
  deferred, execution IDs are exposed for duplicate detection, and governed
  write/confirmation behavior remains unchanged.
- Failed or grounding-insufficient read-action summaries are excluded from the
  final synthesis evidence boundary.
- A blank final model response is reported as `GENERATION_FAILED`; it is never
  returned as a successful empty compound answer.
- A soft extracted-child failure such as a misclassified missing read action no
  longer erases successful sibling evidence. Hard access, policy, confirmation,
  and clarification boundaries still prevent final synthesis.
- Clause order no longer determines whether one successful evidence domain is
  omitted from a compound answer.
- Advanced RAG remains the selected retrieval path during compound evidence
  collection while child answer generation is suppressed.
- Raw public request-context fields are no longer accepted as vector-space
  routing authority. Canonical routing hints are explicitly trusted
  application/server metadata and remain constrained by policy.
- An invalid model-proposed vector space is never silently broadened to every
  available space. A single allowlisted space may be selected as a deterministic
  policy fallback; otherwise normal routing or clarification applies.
- Fanout preserves a document's actual `vectorSpace`, records the
  `queriedVectorSpace`, and drops mismatched hits instead of relabeling them.
- Search-source registries can report a bounded no-match diagnostic. Only
  allowlisted operational fields from registry and adapter diagnostics are
  projected into RAG metadata.

## Migration

Consumers must upgrade the BOM and all AI Fabric artifacts together to
`0.8.12`. No compatibility mode or parallel old/new runtime is required.

Runtime integrations that need to force an exact retrieval scope must populate
`OrchestrationContextMetadataKeys.RAG_VECTOR_SPACE_HINT` or
`RAG_PREFERRED_VECTOR_SPACES` only after authenticating and authorizing a
trusted server caller. Anonymous browser fields such as `vectorSpace`,
`entityType`, `preferredVectorSpaces`, or `retrievalVectorSpaces` are semantic
request context at most and must not be promoted to these trusted keys.

Applications providing a `SearchSourceRegistry` should return only sources
whose canonical entity type matches the already validated request entity type.
If no source matches, implementations may return bounded details from
`resolutionDiagnostics`; credentials, provider handles, private filters, and
document content must not be included.

## Verification

- compound information retrieval across two vector spaces
- grounding-eligible read action plus RAG evidence with exact-once execution
- unusable action-evidence rejection and blank-synthesis failure handling
- soft-child evidence retention and hard-child fail-closed handling
- reverse clause order and explicit partial-evidence handling
- Advanced RAG evidence collection with one final synthesis
- governed write confirmation regression coverage
- trusted and untrusted routing-hint provenance
- invalid vector-space fail-closed and singleton policy fallback behavior
- truthful vector-space fanout metadata and mismatch rejection
- no-source and adapter diagnostic allowlisting
- full affected core/RAG reactor and release guards
