# AI Fabric 0.8.40

## Verified Interactive Caller Identity

Interactive execution now projects the verified initiator as the authentication
subject, not the application-owned subject being processed. A conversation or
account identifier must not replace the signed-in caller in access checks or
outbound action requests.

`TrustedExecutionContext.withCallerIdentity(ExecutionCallerIdentity)` carries
optional, server-verified session, customer, issuer, audience, expiry and caller
classification facts. Tenant, deployment and granted scopes still come from the
trusted execution boundary. Applications must construct these facts from their
verified identity, never request-body metadata or model output. Anonymous callers
cannot acquire authenticated classification or a different anonymous session.

Caller facts are immutable and retained in protected durable specialist, chain
and human-review source envelopes. No access token, refresh token or credential
belongs in this value. Application/machine contexts without explicit caller
identity retain their existing subject/delegation behavior.

## Adoption

Upgrade the BOM to `0.8.40`. Interactive hosts should attach verified caller facts
before orchestration when downstream integrations require session/customer
ownership. Keep the processed subject and conversation binding unchanged.

```java
TrustedExecutionContext trusted = verifiedContext.withCallerIdentity(
    new ExecutionCallerIdentity(
        "END_USER", verifiedAuthMode, verifiedCallerType,
        verifiedSessionId, verifiedCustomerId, verifiedIssuer,
        verifiedAudiences, verifiedExpiry
    )
);
```

Downstream authorization, scope allowlists, required action parameters,
confirmation, anonymous action opt-in and conversation fencing remain enforced.
There are no database migrations or vector reindexing requirements.

## Verification

All 1,411 tests in the affected core, chat-session, execution, actions-connector
and curated-default modules passed with zero failures, errors or skips using the
release profile. All 64 scoped LoomAI runtime authentication/handover/manifest
checks passed, including four real PostgreSQL transaction cases. The 21
runtime-required projects compiled and produced source/Javadoc jars; unrelated
provider/vector matrices were not run for this identity patch.

The `0.8.39` publication attempt was rejected by an old action-proposal assertion
that expected the processed account as the caller. This release corrects that
assertion and additionally asserts that the account subject itself is unchanged.
The failed tag is not rewritten; `0.8.39` is not the consumer release. Hosted
customer-journey acceptance remains separate from framework qualification.
