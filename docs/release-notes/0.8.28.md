# AI Fabric `0.8.28`

- **Release date:** 2026-10-12
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.28`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.28` corrects compound semantic recovery when one model-selected
action is invalid but a sibling obligation is already valid. Recovery remains
LLM-driven for the rejected obligation. The framework now prevents that bounded
recovery call from silently rewriting an already-validated sibling.

## Compound Recovery Correction

- A recovery model may repair only obligations rejected by typed semantic
  validation.
- If the model also changes the type, action ID, or knowledge source of a
  sibling that was not rejected for action semantics, the framework preserves
  the sibling's original structured decision.
- A model-authored `obligationId` may complete a missing structural field while
  the sibling's semantic fields, action parameters, and execution decisions
  remain unchanged.
- The merged response is normalized and passed through the normal extraction
  validator again. Invalid merged output still fails closed.
- Debug metadata records `VALID_SIBLING_PRESERVATION` and
  `SERVER_PRESERVED_VALID_SIBLING`, including both the model proposal and the
  effective structured decision.

This fixes a live compound request in which the model correctly selected an
inventory read action and incorrectly selected an unregistered document action.
The bounded recovery call repaired the document obligation but also changed the
valid inventory obligation to information. The framework now keeps the valid
inventory action and accepts only the permitted document repair.

## Read Actions And Evidence Domains

Read actions remain independent from vector storage by default. An action that
fetches a live or operational entity does not need `groundingVectorSpaces`.
Omitting that optional metadata does not infer a mismatch and does not grant
retrieval access. When the metadata is present, it remains an exact,
server-owned evidence-domain constraint.

## Philosophy And Safety

This correction adds no natural-language matching, phrase rules, token scoring,
domain-specific routing, or deterministic ACTION-to-INFORMATION fallback. The
LLM still authors the repair for the rejected obligation under explicit policy.
Framework code only enforces the previously validated sibling decision,
validates exact identifiers and schemas, emits observable diagnostics, and
fails closed when the merged response is invalid.

## Migration

Upgrade all AI Fabric artifacts through the `0.8.28` BOM. No database migration
or vector reindex is required. Existing semantic-recovery policy names and
configuration remain unchanged.

## Verification

- exact regression for missing compound obligation IDs, one valid live-data
  action, and one unregistered action;
- valid-sibling type, action ID, parameter, and obligation-ID preservation;
- merged-response revalidation and fail-closed behavior;
- read-action validation with omitted `groundingVectorSpaces`;
- complete `ai-fabric-core` suite; and
- semantic-decision source and release-policy guards.

The relationship-query module is unchanged and remains outside this release's
correction claim.
