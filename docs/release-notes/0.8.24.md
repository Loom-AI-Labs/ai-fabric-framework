# AI Fabric `0.8.24`

- **Release date:** 2026-10-11
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.24`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.24` completes the customer-safe `OUT_OF_SCOPE` intent contract.
It removes a hidden canned-response path and requires the semantic response to
come from validated structured model output.

## Structured Out-Of-Scope Contract

- `OUT_OF_SCOPE` now requires a model-authored, customer-safe `directAnswer`.
- The intent validator classifies a missing response as incomplete structured
  output, allowing only the configured bounded model-completion path to repair
  it.
- `OUT_OF_SCOPE` cannot request retrieval, generation, or target resolution.
- The orchestration handler uses only the validated `directAnswer`; arbitrary
  `actionParams` keys are no longer treated as response text.
- If validation is bypassed and the response is absent, handling fails with
  `OUT_OF_SCOPE_RESPONSE_MISSING` instead of manufacturing a successful answer.
- Default, commerce, and support curated prompts now use the same typed field
  and guide the model to produce capability-aware public language.

This correction does not use query keywords, substring matching, plural
guessing, or a domain-specific response table. The LLM remains responsible for
the semantic classification and response. Deterministic code validates only
the typed execution contract and authorization boundary.

## Migration

Upgrade all AI Fabric artifacts through the `0.8.24` BOM. No database migration
or vector reindex is required. Applications that construct `OUT_OF_SCOPE`
intents directly must provide `directAnswer` and set retrieval, generation, and
target-resolution decisions to `false`.

## Verification

- validator tests for complete, incomplete, and execution-bearing
  `OUT_OF_SCOPE` intents
- orchestration fail-closed tests proving the canned fallback is absent
- multi-step extraction tests proving `directAnswer` survives normalization
- complete core and curated-pack test suites
- semantic-decision source guard
- complete framework and real-app release workflows

After publication, downstream consumers must still run their own live-provider
and deployment canaries against the immutable Central artifacts. Those canaries
are adoption evidence, not a pre-publication framework claim.

The relationship-query module is unchanged and remains outside this patch's
correction claim.
