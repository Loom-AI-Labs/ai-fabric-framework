# AI Fabric `0.8.26`

- **Release date:** 2026-10-11
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.8.26`
- **Support policy:** latest release only; mixed or parallel framework/runtime versions are unsupported
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.8.26` makes semantic repair and replanning truthful at the
obligation boundary. A rejected model-selected action can no longer be hidden
by replacing the whole compound result with a different, merely registered
action or unrelated knowledge answer.

## Governed Semantic Recovery

- Unknown-action and action/evidence-domain validation failures now bypass the
  ordinary field-completion path and enter a bounded structured model replan.
- The replan receives typed validation issues, the rejected structured
  decision, exact capability catalogs already present in the system context,
  and the server-owned recovery policy.
- Compound recovery is evaluated by stable `obligationId`. Valid sibling
  obligations must retain their intent type, exact action identifier, and
  valid knowledge source.
- Duplicate compound obligation identifiers are rejected before execution.
- `LLM_REPAIR_THEN_FAIL` may repair an unknown action to an exact registered
  action, but it cannot silently convert it into an information request.
- `LLM_REPLAN_TO_INFORMATION` explicitly permits the model to replan only the
  affected unknown-action obligation to an exact registered knowledge domain.
- An action/evidence-domain mismatch invokes model replanning only under
  `DENY_AND_LLM_REPLAN`. `DENY_AND_FAIL` and `DENY_AND_ALLOWED_RAG` do not call
  or accept a model replan and remain governed fail/defer paths.
- Recovery diagnostics expose the affected obligation, original/effective
  type and action identifier, typed validation decision, outcome, and policy.
- The rejected decision replay is size-bounded and excludes provider/model
  metadata. An oversized recovery context fails visibly.

## Intent Guidance

The default compound, completion, classification, and action-selection prompts
now distinguish performing an outcome from explaining its requirements,
policy, eligibility, effects, or process. An explicit request not to execute
must remain informational. Invalid actions must not be replaced merely because
another action is registered; the model must select an exact capability whose
declared outcome satisfies that obligation.

These are model instructions plus typed validation and policy enforcement.
The implementation adds no query keywords, phrase recognition, regular
expressions, token-overlap ranking, domain-specific routing, or hidden success
fallback. The configured LLM remains the semantic authority and unresolved
decisions remain visible.

## Migration

Upgrade all AI Fabric artifacts through the `0.8.26` BOM. No database migration
or vector reindex is required.

Keep `unknownAction=LLM_REPAIR_THEN_FAIL` unless the deployment explicitly
permits knowledge-backed model replanning. A deployment that intentionally
supports that behavior must set `unknownAction=LLM_REPLAN_TO_INFORMATION` in
its server-owned semantic recovery profile. Existing action-domain policy names
are unchanged, but `DENY_AND_FAIL` and `DENY_AND_ALLOWED_RAG` are now enforced
strictly before the replan model is called.

## Verification

- per-obligation unknown-action allow/deny tests;
- action/evidence-domain replan and no-replan policy tests;
- valid sibling preservation and duplicate-obligation rejection tests;
- bounded recovery-prompt and metadata-exclusion tests;
- focused progressive extraction, multi-step prompt, and validator tests;
- complete core and framework release suites; and
- semantic-decision source guard and release-policy guards.

The IT-support real-app seed lifecycle is also transactionally serialized and
idempotent by natural identifier. This closes the startup-versus-demo-seed race
detected by the packaged P1 release smoke without changing framework semantics.

Downstream products must still run real-provider and deployment-local canaries
before production promotion. The relationship-query module is unchanged and
remains outside this release's correction claim.
