# AI Fabric Framework 0.8.66

## Bounded Manager Directive Repair

Schema-bound specialist output can pass JSON Schema validation but fail typed
conversion, including a directive with incompatible fields or a blank completion
message. Previously the chain reported a generic invocation failure after the
manager had already completed its generation.

- Identify post-execution typed-output binding failure separately from provider,
  authorization, and invocation failures, without retaining raw output in the
  exception or its cause.
- Route manager binding failures through the existing directive-correction
  policy. The configured correction count, deadlines, model admission, token
  limits, and spending limits do not change.
- Give the model the executable directive contract and current approved targets,
  completed results, and remaining budget. The framework does not select a
  replacement directive or invent facts.
- Retain completed worker findings. A format correction does not replay a worker
  or bypass target eligibility, ownership, consent, or write confirmation.
- Record safe typed-binding phase, invocation ID, correction count, and completed
  result count. Exhausted repair has a specific visible failure code.

This builds on 0.8.65's separation of manager planning from worker evidence
finalization. Ordinary worker output and general invocation failure handling are
unchanged; the typed specialist client does not perform its own retries.

## Verification

Focused regression coverage includes typed conversion classification and payload
redaction, cross-field and blank-message failures, a repaired directive after
completed work, disabled and exhausted correction policy, provider and permission
failure isolation, and existing chain authorization and execution bounds.

The release-profile reactor, release guards, and minimal Spring Boot consumer are
qualified separately before publication. Production application quality remains
an application-level qualification, not a claim made by the framework release.
