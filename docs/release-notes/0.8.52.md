# AI Fabric 0.8.52

## Scope

Generic answer generation no longer substitutes raw READ evidence, a fixed
no-context answer or a deterministic post-action summary after provider failure
or empty output. Generation makes one configured call; an empty structured,
budgeted or attachment-bearing call is not retried as a text-only request.
Handler messages are preserved regardless of wording instead of being suppressed
by generic-phrase matching in the generic post-action path.

An information answer that cannot be generated returns an explicit failure with
the authorized retrieved documents or executed READ receipts retained. No optional
next steps are advertised for that failed answer. Retrieval-only and explicitly
disabled-generation behavior remain supported.

If an action already executed successfully, narration failure does not undo it,
change its execution success or replay the side effect. Its original handler
message, execution ID and receipt remain. No substitute answer/summary is created.
Safe `metadata.postActionGeneration` exposes `used`, `skippedReason` and
`errorCode=GENERATION_FAILED` so consumers can show a separate narration warning.
Provider exception details are not included in this generic public status.

No new semantic matcher, forced source selection, retry policy, action permission
or confirmation bypass is introduced. Relationship-specific deterministic fallback
behavior remains explicitly deferred; this patch does not remove it.

## Consumer Impact

Adopt the 0.8.52 BOM, rebuild and apply the compatible executable artifact.
Existing deployed immutable releases do not update automatically. No database
migration, reindexing, source replacement or vector copying is needed.

Consumers must distinguish action execution from narration: successful receipt
plus failed narration is not an invitation to repeat the action. A consumer may
show the original receipt with a separate explanation-unavailable notice. A
failed information answer must not be relabelled successful from its evidence.
Apps that relied on implicit fallback prose must handle the explicit failure;
no new fallback configuration is required or enabled by this patch.
