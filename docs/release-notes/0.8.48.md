## Scope

- Preserve optional action-level native `inputSchema` and `outputSchema` from
  connector catalogues through canonical metadata, planners, Spring AI tool
  definitions, and runtime action config. Existing simplified forms remain.
- Validate resolved native arguments with networknt rather than a lossy type
  projection. Empty schema objects, omitted root type, qualified root unions,
  nested nullable values, numeric enums and decimal bounds are supported.
  Output metadata is not forced into an object-shaped schema.
- Pin offline validation to qualified Draft 2020-12 and Draft 07. Clear all
  resource loaders, allow only bundled metaschemas, and reject external refs
  and unknown/file/classpath dialect declarations. Schema declarations never
  authorize resource fetching.
- Run full executable native validation only at dispatch, after normal
  resolver and confirmation preparation and before action-start guards and
  connector/SPI calls. Incomplete collection and proposal preflight retain
  their existing provided-value validation behavior.
- Preserve explicitly supplied JSON null through Intent setters/normalization,
  multi-step extraction, action context, read proposals, draft continuation,
  confirmation serialization and protected receipts. Absent fields remain
  absent. Native schemas decide whether a present null is executable; hidden
  or evidence-bound required bindings are not waived by a null value.
- Use the same native validator for durable proposals and include native
  schemas in the existing receipt contract hash. Canonical protected payloads
  preserve null even when the host mapper omits nulls, preventing null/absent
  parameter-hash collisions.
- Omit exact boolean `enabled: false` actions from catalogue registration.
  Omitted/true remain enabled. No new enabled record field or policy API.
- Disable automatic connector retries for MCP WRITE_ONLY/READ_WRITE by
  default. A generated key alone is insufficient. Only an explicitly qualified
  receiver deduplication contract opts into configured retries. Existing HTTP
  retry behavior and bounded MCP READ retries are unchanged.
- Reuse the existing runtime-context binding lookup in read planning before
  required/provided checks, deduplication and dispatch. Configured trusted
  fields overwrite model values; missing trusted values cannot be replaced by
  spoofed planner inputs. This does not invoke recursive reads, attachment
  fallbacks or any new authority source.

This is generic framework support, not new MCP discovery/authentication APIs,
autonomous agents, schedulers, recovery mechanisms or a second execution path.
The existing `McpActionExecutor` SPI and gateway properties are unchanged.

## Consumer Notes

The BOM manages networknt `3.0.0`, matching MCP SDK 2.0.0's validator dependency.
Framework Jackson 2 DTO and public method signatures remain unchanged; internal
schema helpers use standard JSON-string APIs to cross the Jackson boundary.
Consumers directly calling networknt's old Jackson-2-node overloads must adapt
those vendor calls as well. Do not force 2.0.1 over the MCP SDK's required
version or disable schema validation to avoid the linkage error.

Keep all framework modules aligned through the 0.8.48 BOM. This candidate is
installed under new version coordinates; it must not overwrite 0.8.47.

An explicit `inputSchema: {}` opts into an empty native contract. Null/omitted
schema fields retain simplified validation. An explicit parameter null is now
retained as JSON data rather than removed; old required non-native parameters
continue to treat null as missing. Receivers must apply their declared native
schema, authorization and confirmation policies.

Trusted parameter collection metadata remains in `params`, for example:

```yaml
params:
  - name: scopeKey
    type: STRING
    required: true
    askUser: false
    visibility: INTERNAL
    resolveFrom: {source: RUNTIME_CONTEXT, field: userId}
```

The full upstream input schema remains intact for dispatch; the public
collection projection does not ask customers to supply this trusted field.
Schemas combining hidden bindings with complex root references/conditionals
need separate qualification. Do not claim general existential projection of
arbitrary hidden-dependent JSON Schema constraints.

Native schema hashes now participate in proposal receipts. A native contract
change invalidates older pending native proposals instead of silently applying
new validation semantics. Hosts whose mapper previously omitted nulls can also
see a receipt hash change when a contract or parameter payload contains null;
recreate pending proposals rejected for a changed contract/hash rather than
replaying them under different semantics. There is no database migration,
vector copying, reindex requirement or change to public execution-result shape.
