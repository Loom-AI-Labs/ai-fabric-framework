# AI Fabric `0.7.1`

- **Release date:** 2026-09-20
- **Maven group:** `io.github.loom-ai-labs`
- **Tag:** `ai-fabric-framework-v0.7.1`
- **Upgrade baseline:** `0.7.0`
- **Java:** 21
- **Spring Boot:** 4.1.x

AI Fabric `0.7.1` is a focused production patch for PostgreSQL-backed
durable specialist execution and human-review state transitions.

## Fixed

`JdbcDurableExecutionRepository` and `JdbcReviewTaskRepository` now bind
nullable expected lease owners as explicit JDBC `VARCHAR` parameters. This
matches the existing specialist-chain repository behavior and prevents
PostgreSQL from rejecting compare-and-set transitions with:

```text
ERROR: could not determine data type of parameter
```

The defect could leave queued asynchronous specialist work unable to
terminalize or recover when the expected lease owner was null. The same
latent issue existed in review-task transitions. H2 accepts the untyped null,
which is why the portable repository tests did not expose the production-only
failure earlier.

## Compatibility

- No public API or configuration contract changed.
- No database schema or migration changed.
- Existing execution, chain, review, and idempotency records remain valid.
- Applications using in-memory state are behaviorally unchanged.
- PostgreSQL deployments can upgrade in place while retaining their existing
  state tables and protection secrets.

## Verification

- The framework execution reactor passed with 1,170 tests and zero failures.
- Durable execution, declarative-chain, and review JDBC repository suites all
  passed, including null-to-leased and leased-to-terminal compare-and-set
  transitions.
- A PostgreSQL 16 Testcontainers regression proves null-to-leased transitions
  for both durable specialist execution and review tasks.
- LoomAI live verification uses a PostgreSQL-backed Smart Brain operation to
  prove the corrected asynchronous transition path after publication.
