# AI Fabric Framework 0.8.64

## Scope

Bounded repair of an unsupported `requiresTargetResolution` model decision.
An authorized parameterless tool can resolve its selected resource on the
application backend without a chat attachment. The model now receives the visible
selected action's input requirements and can correct that flag before execution.

This applies to model-directed chat and specialist workers. It does not enable
ordinary orchestration or generic context-answer fallback for structured-only
chain managers. General chat retains its configured final context-answer policy;
an exhausted specialist repair remains an explicit execution failure, not a
fabricated request for customer information.

## Boundaries

- Uses the existing shared decision-recovery round and admission-time budgets.
- Changes only the target-resolution flag, never an action, parameter or identity.
- Does not synthesize target IDs or expose argument values in repair feedback.
- Filters action contracts through the existing effective capability profile.
- Preserves conversation ownership and NEVER-persist history isolation.
- Leaves required input, trusted-value, action access and confirmation checks in
  the governed execution path. Supplied attachments are still resolved first.
- Uses managed target-system/target-user prompts, without lexical routing or
  generated-answer replacement. A real missing choice gets a model question.

## Qualification

The 31-module release-profile build passed: 2,619 tests, zero failures/errors,
and three credential-dependent real-provider cases skipped. This includes nine
target-decision regressions; the earlier focused recovery/governed-invocation
suite is a subset, not additional tests. The minimal consumer compiled and the
release guards passed.

The wider real-app consumers are not an all-green suite: Incident Investigation
Room retains failures reproduced on 0.8.63, and Agentic AI Action Resolver has a
schema-bootstrap error also reproduced on 0.8.63. The other consumer modules
passed across the initial and resumed runs. Neither unrelated issue is changed
by this bounded patch.

Downstream/runtime qualification and publication are separate gates. Local
installation alone is not Maven Central availability, and a public release is
not a deployed application. Real-model hosted checks remain required.
