# 0.8.62 - Action Contract Failure Context Handoff

Fix the ordinary-chat terminal handoff after bounded extraction repairs exhaust
an invalid model-generated action parameter. Such a candidate now reaches the
existing single context-answer generation instead of a generic intent-analysis
error. Live qualification of 0.8.61 exposed this with an unsupported product
category after three repair rounds.

Parameter validation remains unchanged: the invalid candidate never becomes an
executable intent. This is an answer-only recovery, not permission to coerce
values, call tools, retrieve new evidence, bypass confirmation or replay a write.
Provider failures and combined protected action/confirmation failures retain
their failure path. Strict Task/specialist contracts stay excluded.

Regression coverage exercises the actual extraction-to-final-answer handoff,
including mixed failures and provider failure. An opt-in real Spring AI case
qualifies final generation from owned history after a controlled action-contract
failure. Existing request-shared limits, accounting, source authorization,
Automatic/Selected evidence policy and one-final-answer limit are unchanged.
