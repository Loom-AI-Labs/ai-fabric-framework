# AI Fabric 0.8.42

## Read Planning Context And Evidence Budgets

Three bounded generic corrections improve the information available to the
model. They do not replace semantic decisions with text matching, grant
retrieval access, or add automatic all-source recovery.

- Both managed compound-extraction templates now describe the existing
  validator contract: explicit `needsAdvancedRAG` on every INFORMATION intent
  and unique, nonblank compound `obligationId` values. Source selection follows
  the effective server policy; omission no longer promises routing/fan-out.
- The read-action planner receives the authorized vector-space catalogue and
  source-selection/recovery constraints, including the effective execution
  profile intersection. It can choose relevant indexed evidence even when
  extraction initially requested no retrieval. No provider-wide document
  counts or unapproved source statistics are added. Existing execution and
  retrieval authorization remains authoritative, including a repeated check
  after the planner introduces retrieval that extraction did not request.
- Read-action evidence lists use a server-configurable bounded item limit
  instead of an unconditional five-item cap. Character/depth/map budgets and
  explicit truncation markers remain in force. READ actions do not acquire a
  new requirement to have indexed grounding or a vector space.
  Fallback action payloads are sanitized once, preserving numeric types and
  original truncation counts. Character compaction that removes all useful
  facts cannot claim usable grounding; trusted explicitly authoritative empty
  results still retain their existing contract.
  The aggregate context also retains complete action-evidence blocks only;
  budget-omitted actions are visible in diagnostics and cannot make an
  action-only answer appear grounded.

## Configuration

```yaml
ai:
  orchestration:
    modes:
      executor:
        read-action-resolution:
          max-action-evidence-items: 10
          max-action-evidence-chars-per-action: 8000
```

`max-action-evidence-items` defaults to 5 and accepts 1 through 100. Invalid
operator configuration is rejected at binding/policy construction; it is not
silently normalized. A larger item budget does not override character budgets
or guarantee that every item fits. Debug orchestration policy and read-planner
diagnostics expose the effective budget; the budget participates in execution
profile identity.

No database migration, source-data migration, or reindexing is required. Update
the BOM and framework artifacts consistently to `0.8.42`, then rebuild the
consumer. Direct Java construction of the internal read-resolution policy or
service must supply the new item budget/entity-configuration dependency.
Normal Spring-managed consumers bind the default automatically.

## Validation Philosophy

The framework philosophy now explicitly distinguishes hard trust/side-effect
boundaries, minimal necessary execution structure, and measured semantic
quality. This release aligns prompts with current validation; it does not add
or relax validator rejection rules. Missing optional optimization hints are not
inherently security violations. Any future change to an existing validator is
a separate reviewed implementation decision.

## Scope And Qualification

The versioned affected-module release build passed 896 checks: 883 Core and
13 default-curated checks, zero failures/errors/skips. The focused 125-check
subset is included, not additional. It covers both real prompt overlays,
six-record evidence, character limits, effective-profile source restrictions,
retrieval-disabled/required-allowlist cases before and after planning, visible
missing model selection, and a non-grounding READ without RAG. Repository
release guards passed; source and Javadoc artifacts were produced.

Central-only consumer qualification and hosted real-provider canaries are
still pending at preparation time; no deployed answer-quality improvement is
claimed from deterministic tests alone. Unrelated provider/relationship
matrices are outside this bounded patch. Partial-compound final synthesis and
application-specific action-filter completeness are not included.
