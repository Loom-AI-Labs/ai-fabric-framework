# AI Fabric 0.8.59

## Prepared Action Evidence Is Authoritative

Fix a legacy READ path that appended `actionResultData` after the handler had
already prepared its evidence. That could bypass selected fields, credential
exclusions and truncation from automatic preparation. Both ACTION-classified
READ generation/observations and INFORMATION read planning now use only the
handler-prepared facts. Empty, absent or failed preparation never expands back
to raw result data or pinned targets. Cooperative retrieval's status-only
fallback likewise no longer includes raw action data.

Connector actions retain the automatic preparation introduced in 0.8.58, and
explicit selections remain authoritative. Native annotated actions that want
their results used as model evidence must supply their existing `@ActionFacts`
contract; an absent facts contract is no longer overridden by forced generation.
This is an evidence-exposure boundary, not a new semantic validator.

The original approved `ActionResult` and completed write receipt remain intact
for the application's normal result handling. Evidence selection is not a
replacement for a suitably narrow customer-visible output contract. No action
is replayed, and no extra model call, authorization, confirmation, source-filter
or call-budget change is introduced. Relationship-specific generation is not
changed by this patch.

## Qualification

New secret-canary and failure-injection tests cover normal and forced generation,
read observations, INFORMATION planning, explicit empty selections, absent facts
and projection failure. They verify excluded output never returns through raw
fallback and successful result receipts remain intact. Release-reactor and live
qualification must be reported from their actual completed runs, not inferred
from these focused tests.
